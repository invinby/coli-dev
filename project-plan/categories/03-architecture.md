# 03. macOS-архитектура

## Подтверждённое требование

Целевой продукт — полноценная платформа для macOS с онлайн- и офлайн-режимами. Пользователь просит аккуратный интерфейс, организованный с учётом принципов Apple.

## Текущее состояние

Текущий репозиторий содержит Python/FastAPI-оркестратор и прежний веб-интерфейс. SwiftUI-клиент в macOS/ColiDev содержит каталог шести направлений и обращается к /health, /chat/stream и локальному API ключей. В UI есть автоматический и локальный режимы; доступность маршрутов считается по облачному соединению, лимиту сессий и готовности Ollama. Retrieval использует подключённый Obsidian vault и отдельный офлайн-индекс курсов с лексическим поиском и опциональной локальной семантикой через Ollama. В настройках можно вводить ключи Gemini, Kimi и Obsidian; backend сохраняет их через macOS Keychain, показывает только статус/источник и сохраняет .env как dev-fallback. `/health` сообщает имя настроенной локальной embedding-модели без секрета, а SwiftUI показывает, включена ли такая настройка; это не проверка фактической доступности модели. Ключевые API-маршруты доступны только с loopback и отклоняют посторонний Origin. Local-only использует отдельный HTTP-клиент без системных proxy и разрешает Ollama только на loopback; Obsidian REST тоже ограничен loopback. UI блокирует неподтверждённые адреса. Шесть bilingual Markdown-карт включены в Resources-folder `02_Areas` внутри macOS app bundle; SwiftUI разбирает базовый, промежуточный и продвинутый уровни, показывает цели модулей и ведёт к текущему стартовому уроку. Физический starter lab получил одну вращаемую SceneKit-сцену для наглядного сравнения силы и массы; полный 3D-движок уроков пока отсутствует. CI workflow проверяет сборку приложения и наличие каждого curriculum-файла внутри app bundle. Commit `112ec62` прошёл run 37243523767: backend checks и macOS build успешны. Семантика проверена mock-тестами, но не реальным Ollama; UI пока не запускался на пользовательском Mac. Пользовательский Keychain и живой grounding тоже остаются непроверенными. Полный web-RAG пока не реализован.

## Первый реализуемый срез

SwiftUI-клиент читает встроенный учебный каталог и сохраняет язык, маршрут AI и отметки прохождения через UserDefaults. Отдельный клиент обращается только к localhost API: проверяет состояние, передаёт язык и режим, добавляет контекст урока и диалог, затем отображает SSE-ответ. Экран настроек принимает ключи через SecureField; локальный backend записывает их в macOS Keychain и никогда не возвращает значение в UI. `.env` остаётся dev-fallback, а статусы Keychain и переменных окружения не раскрывают сами ключи. Следующий шаг — подтвердить свежую macOS-сборку и продолжить проверку онлайн/локальных сценариев.

Для финального этапа Auto отдельный loopback-only API позволяет выбрать провайдера и model ID (Gemini, Kimi, OpenRouter или Ollama); маршрут хранится локально без API-ключей и редактируется из Control Center. В режиме платных маршрутов по умолчанию остаётся Gemini 3.1 Pro Preview, при сбое итоговой модели общий резервный ответ формирует локальная Ollama. По умолчанию включён free-only режим, который ведёт Auto через `openrouter/free` или локальную Ollama. Остальные роли черновиков Auto пока не имеют полного редактора маршрутов, поэтому переключение финализатора не делает весь Auto локальным.

Настройка расходов Auto по умолчанию закрывает потенциально платные API: облачный черновик/финал допускаются только через точный OpenRouter Free router `openrouter/free`, критик и verifier остаются на локальном Ollama; без ключа OpenRouter приложение использует локальную модель. Пользователь может явно включить платные маршруты в Control Center. Этот барьер относится к обычному Auto; Google Search — отдельное opt-in действие с отдельным предупреждением о возможной оплате.

## Локальный прогресс и интервальное повторение

Backend хранит оценки повторения в отдельной SQLite-базе в пользовательской папке данных ОС; `COLIDEV_DATA_DIR` позволяет переопределить её. `GET /learning/progress` возвращает записи и число наступивших повторов. `POST /learning/reviews` принимает оценку 0–5 и UUID события, применяет SM-2-подобный интервал и дедуплицирует повторы запроса. Оба маршрута ограничены loopback-клиентом и проверкой Origin. Общий SwiftUI-экран отправляет lesson ID любого открытого course-модуля после quiz и learner confirmation; очереди повторов не нужен отдельный route или список разрешённых уроков. Он синхронизирует оценки при запуске, показывает наступивший повтор и держит неотправленные события в UserDefaults, пока backend недоступен. Проверка endpoint-ов теперь отдельно покрывает module lesson ID `mathematics.numbers_fractions_and_percentages`; реальное offline-to-online взаимодействие и UI всё ещё требуют приёмки на Mac.

Отдельная ручная проверка ссылок на источники использует неизменяемый allowlist образовательных доменов, извлекает HTTPS-ссылки только из встроенных уроков, ограничивает concurrency/таймаут и сохраняет ETag/Last-Modified в пользовательской SQLite-базе. Loopback-only endpoint не принимает URL от клиента и не следует редиректам. Он проверяет доступность и версию страницы по HTTP-метаданным; содержимое не входит в RAG, а фактологическая редактура остаётся ручной.

Для свежей установки индекс, сессии и прогресс используют общую per-user data root: macOS `~/Library/Application Support/coli-dev`, Windows `%LOCALAPPDATA%/ColiDev`, Linux `$XDG_DATA_HOME/coli-dev` (либо стандартные fallback-папки). `COLIDEV_DATA_DIR` переопределяет data root, `COLIDEV_LOG_DIR` — отдельный каталог логов. Если база прогресса или JSON-сессий найдена в прежнем каталоге, backend продолжает читать её, чтобы не потерять локальные данные при обновлении.

## Предварительное архитектурное предложение

Рассмотреть нативный SwiftUI-клиент для macOS, общий учебный доменный слой, локальное хранилище курсов/прогресса/индекса и отдельный слой AI-провайдеров. Существующий FastAPI-код оценить на повторное использование; не переписывать его и не переносить в приложение без аудита.

## Блоки целевого продукта

- Интерфейс macOS: каталог, учебный экран, практика, ИИ-тьютор, визуальная лаборатория, библиотека источников и настройки.
- Учебное ядро: курсы, уроки, задания, прогресс, повторение и профиль.
- Локальный слой: кэш курсов, индекс RAG, пользовательские данные и модели, если устройство справляется.
- Онлайн-службы: поиск/обновление источников, облачные модели и резервные провайдеры.
- Интеграционный слой: Obsidian и проверенный способ взаимодействия с NotebookLM.
- Визуальная лаборатория: схемы, симуляции и 3D только там, где это улучшает понимание.

## Будущая Windows-версия и общая платформа

Подтверждённое направление: после macOS-релиза выпустить Windows-клиент с функциональным паритетом. Учебные материалы, доменная логика, API-контракты и максимально возможная часть Python/FastAPI backend должны оставаться общими. UI и системные интеграции проектировать отдельно под каждую ОС.

Для Windows отдельно предусмотреть безопасное хранение API-ключей через системное хранилище учётных данных, пути данных пользователя, запуск и остановку backend, работу Ollama, файловые разрешения и упаковку runtime. Нельзя считать, что Keychain, SwiftUI или macOS-упаковку можно перенести как есть.

Открытые технические решения: нативный Windows UI или кроссплатформенный стек; будет ли сохранён отдельный SwiftUI-клиент macOS; общий механизм обновлений; форматы пакетов и требования к подписи. Решение принять после стабилизации функций macOS и короткого технического прототипа, сравнив стоимость поддержки двух UI с переходом на общий UI-стек.

## Apple-style интерфейс

Использовать нативные паттерны macOS, логичную иерархию навигации, системную типографику и компоненты, ясные состояния загрузки/ошибки/офлайна, доступность клавиатуры и VoiceOver, сдержанную анимацию и адаптацию под разные размеры окон. Проверять детали по [Apple Human Interface Guidelines: Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) и [Navigation and search](https://developer.apple.com/design/human-interface-guidelines/navigation-and-search) перед разработкой.

Визуальное направление: спокойная научная мастерская, не шаблонный неон и не клон чата. Учебная часть должна давать место чтению, аккуратной типографике, схемам и интерактивной сцене; управление — точные таблицы, фильтры, происхождение и явные статусы. Использовать системные semantic colors и SF Symbols, аккуратные предметные акценты, многоуровневую типографику, редкие материалы/translucency только в системной навигации/toolbar, и управляемый контраст для предупреждений. Не заменять понятные labels и графики на glow, градиенты и декоративные карточки.

Референс-процесс: разобрать конкретные shipped macOS-приложения по отдельным задачам, а не копировать общий скриншот: Apple Books/Swift Playgrounds — чтение и обучение; Xcode — плотное рабочее пространство со списком и инспектором; Activity Monitor/Console — системные состояния и диагностика; Obsidian — организация базы заметок и ссылок. Сверить реальные текущие интерфейсы и HIG перед visual pass. Для каждого паттерна записать, какую задачу он решает в ColiDev; заимствовать только уместную структуру и взаимодействие, не фирменную оболочку.

## Панель управления и административный backend

Панель — отдельный пункт нативной навигации и отдельные рабочие представления: обзор; курсы/версии; официальный реестр источников и очередь перепроверки; RAG/индексация; провайдеры/агенты/usage; интеграции; диагностика/backup. Не сваливать всё в один `SettingsView`. Первый RU/EN срез уже добавляет native Control Center, сводку, реестр источников, состояния сервисов и действия `check references`/`refresh local index`. Реестр читает loopback-only `GET /knowledge/sources` и отделяет дату редакторской проверки урока от HTTP-проверки и `Last-Modified`. В Services добавлены переносимый JSON export/merge прогресса с явным предупреждением о незашифрованных заметках; полное восстановление настроек, истории, индекса и секретов не входит. Следующими этапами подключить редактор курсов/версий, инспектор RAG, назначение моделей, диагностику и более полный backup/restore.

Все новые admin endpoints сохраняют loopback/Origin-guard, фиксированный список безопасных источников, жёсткие лимиты результатов и времени и отсутствие текстов чата/API-ключей в логах. Произвольные URL не принимаются от retrieval-клиента; единственное явное исключение — пользовательская настройка OpenAI-compatible base URL, где backend требует HTTPS для remote endpoint и loopback для HTTP. Изменение validator только создаёт редакторское уведомление; публикация нового текста, переиндексация и запись редакторского решения должны быть отдельными, тестируемыми этапами. Панель показывает API/data-schema version, чтобы несовпадающая версия сервера не выглядела готовой.

В Control Center добавлена конфигурация одного пользовательского OpenAI-compatible провайдера: HTTPS base URL (или HTTP только на loopback), model ID и отдельный API key в macOS Keychain. Base URL/model сохраняются локально без секрета. Новый провайдер доступен в предметном specialist и final-synthesis маршрутах; Auto вызывает его только при явном разрешении потенциально платных маршрутов, иначе переходит на локальный Ollama. Настройка сообщает о наличии URL/model/key, но не объявляет API проверенным до реального запроса. Streaming для этого провайдера пока не подключён: токены выдаются после полного ответа.

## Архитектурные решения, которые ещё не утверждены

- SwiftUI выбран для первого нативного клиента. В Xcode-проекте пока стоит macOS 13 как прототипная цель; минимальную версию релиза нужно подтвердить.
- Какие части остаются в Python/FastAPI и как клиент с ними общается.
- Формат локального хранения и шифрование личных данных.
- Синхронизация между устройствами, если она понадобится.
- 3D-стек и требования к GPU/памяти.
