# 11. Обратная связь и критерии готовности / Feedback and acceptance criteria

Этот список собирает правки, переданные командой 8 октября 2026 года. Он задаёт порядок исправления прототипа и критерии, по которым можно принять работу. Планы, проверки кода, сборка и ручная проверка на Mac считаются разными уровнями готовности.

This list records the team's feedback received on 8 October 2026. It sets the prototype-fix order and acceptance criteria. Plans, code checks, builds, and hands-on Mac review count as separate levels of readiness.

## Уточнение по предмету «Биология» / Clarification about Biology

**RU:** Последняя поправка команды отменяет прежнюю трактовку, будто нужно создавать биологию заново или добавлять её как новый встроенный предмет. Биология уже входит в стандартный каталог. Требование — дать ученику возможность самому создать новый предмет и добавлять темы и подтемы как в пользовательские, так и в существующие предметы. Общая проверка навигации по встроенным урокам остаётся нужна, но отдельный дефект открытия биологии не считать подтверждённым без воспроизведения.

**EN:** The team's latest clarification supersedes the earlier interpretation that Biology should be created again or added as a new built-in subject. Biology is already in the standard catalog. The requirement is to let learners create new subjects and add topics and subtopics to both custom and existing subjects. General navigation checks for built-in lessons still apply, but do not treat a Biology-specific opening bug as confirmed unless it is reproduced.

## Приоритеты / Priorities

| Приоритет | Требование по-русски | Requirement in English | Критерий приёмки / Acceptance criterion |
|---|---|---|---|
| P0 — исправность | Статус оркестратора должен различать работающий backend, настроенный маршрут и подтверждённый ответ модели. Тьютор должен отвечать через выбранные локальный и разрешённый облачный маршруты, а при сбое объяснять причину. | Orchestrator status must distinguish a working backend, a configured route, and a model that has actually replied. The tutor must answer through the selected local and allowed cloud routes and explain failures. | Отдельно проверить backend health, Ollama и облачный маршрут; сделать минимальный сквозной запрос тьютора к каждому маршруту. Не показывать «ответ модели проверен», пока модель не ответила. Проверять облако только при явно выбранной бесплатной политике; любые проверки, расходующие квоту, запускать только по действию пользователя с ясным предупреждением. / Check backend health, Ollama, and the cloud route separately, then send a minimal end-to-end tutor request through each route. Do not show “model response verified” until a model has replied. Probe cloud only under the explicitly selected free policy; run any check that consumes quota only after a clear user action and warning. |
| P0 — навигация | Ни один ожидаемый экран не должен заканчиваться состоянием вроде «материал не найден», если у предмета есть урок. Не создавать копии встроенных предметов для обхода проблем навигации. | No expected screen should end at “material not found” when a subject has a lesson. Do not duplicate built-in subjects to work around navigation problems. | Проверить переходы из каталога, дорожной карты, карточки урока и кнопки «Продолжить». Для каждой ссылки проверить наличие целевого ресурса и осмысленную ошибку для отсутствующей темы; отдельно подтвердить, что стандартная «Биология» уже есть в каталоге. / Check routes from the catalog, roadmap, lesson card, and Continue action. Verify each target resource and a useful missing-topic state; separately confirm that built-in Biology remains in the catalog. |
| P1 — качество заданий | В случайном порядке показывать варианты ответа при каждой новой попытке; во время вопроса не менять соответствие варианта правильному ответу. Разбирать и верный, и неверный ответ. | Shuffle answer choices on each new attempt while keeping the answer mapping stable during the question. Explain both correct and incorrect answers. | Автоматически проверить корректность индекса, появление правильного варианта на разных позициях и сохранение результата после перемешивания. / Automatically verify the answer mapping, varied correct-answer positions, and correctness after shuffling. |
| P1 — достоверность | Указывать для учебного утверждения официальный или научный источник, дату проверки и область действия. Не выдумывать ссылки, исследования и свежесть. Спорные положения помечать. | Provide an official or scientific source, review date, and scope for sourced learning claims. Do not invent citations, studies, or freshness. Mark disputed claims. | Для каждого готового урока проверять рабочие ссылки, точность тезисов и лицензионные ограничения. Проверка источников не должна незаметно переписывать урок. / Check links, claims, and licensing for each finished lesson. Source monitoring must not silently rewrite a lesson. |
| P1 — последовательность | Строить темы от необходимых основ к продвинутым и научным уровням; переходить дальше по подтверждённому пониманию, а не по факту открытия страницы. | Sequence topics from prerequisites through advanced and, when appropriate, scientific levels. Advance based on demonstrated understanding, not merely opening a page. | Для курса видны предпосылки, текущий этап и следующий шаг. Освоение проверяется объяснением, применением и хотя бы одной новой задачей. / Show prerequisites, current stage, and next step. Check mastery with explanation, application, and at least one novel problem. |
| P2 — персонализация | Учебный план учитывает ответы, типы ошибок, скорость, самостоятельность и уверенность ученика; изменяет сложность и повторение. | The study plan considers answers, error types, pace, independence, and confidence, then adapts difficulty and review. | Изменение результатов должно менять следующий рекомендуемый шаг; слабые основы требуют конкретного возврата, сильный результат открывает более сложное задание. / A change in learner results must change the recommended next step: weak prerequisites trigger a focused review; strong performance unlocks harder work. |
| P2 — авторский каталог | Биология и остальные встроенные предметы сохраняются. Ученик может создать собственный предмет, добавлять темы в него и в существующие предметы, создавать подтемы и задавать русские и английские названия. | Keep Biology and all other built-in subjects. Let the learner create a subject, add topics to it or an existing subject, create subtopics, and provide Russian and English titles. | Новые предметы не дублируют встроенные; дерево, цели и заметки сохраняются локально, открывают тьютора по стабильному ID и могут удаляться вместе с вложенными темами. / Custom subjects cannot duplicate built-ins; the tree, goals, and notes persist locally, open the tutor through a stable ID, and can be deleted with their descendants. |
| P2 — визуализация | Выбирать визуальный формат по механизму темы: интерактивную схему, график, симуляцию, видео или управляемую 3D-модель. 3D нужен там, где помогает пониманию, а не ради эффекта. | Choose diagrams, graphs, simulations, video, or manipulable 3D according to the concept. Use 3D when it improves understanding, not as decoration. | У каждого интерактива указаны управляемые параметры, что ученик может наблюдать, и ограничения модели. Для каждого видео — контекст и вопросы для проверки. / Each interactive activity identifies its controls, observable result, and model limits. Each video includes context and comprehension questions. |
| P3 — покрытие | Расширять содержание по всем приоритетным направлениям и уровням; число карточек не считать доказательством полноты программы. | Expand content across all priority fields and levels; the number of cards is not proof of curriculum completeness. | Показывать реальные готовые уроки, языковую полноту, источники и пробелы отдельно для каждого предмета. / Report finished lessons, language coverage, sources, and gaps separately for each subject. |

## Рекомендуемый цикл занятия / Recommended lesson loop

**RU:** Диагностика → короткая цель → объяснение подходящей глубины → визуальное исследование → пример → самостоятельная практика → усложнение по результату → разбор ошибки → проверка переноса в новую задачу → фиксация выполненного → следующий шаг или повторение. Порядок меняется под предмет и состояние ученика, это не обязательный одинаковый шаблон.

**EN:** Diagnosis → a short goal → level-appropriate explanation → visual exploration → example → independent practice → result-based challenge → error analysis → transfer to a new task → record what was completed → next step or review. Adapt the order to the subject and learner; do not apply one rigid template.

## Ограничения и честная готовность / Limits and honest readiness

- **RU:** Индекс RAG и дата проверки источника не гарантируют, что текст урока автоматически обновился. Любое обновление содержания требует проверки редактором и фиксации источника.
- **EN:** An RAG index and source-check date do not mean lesson text was automatically updated. Content changes require editorial review and a recorded source.
- **RU:** Локальный API, готовый провайдер и реально ответившая модель — три разных состояния. Интерфейс и диагностика должны различать их.
- **EN:** A local API, a configured provider, and a model that actually answered are three different states. The UI and diagnostics must distinguish them.
- **RU:** Кодовая проверка Swift-модели не заменяет Xcode-сборку; Xcode-сборка не заменяет ручную проверку навигации, отображения, клавиатуры и VoiceOver на Mac.
- **EN:** A Swift model check does not replace an Xcode build. An Xcode build does not replace hands-on Mac review of navigation, rendering, keyboard access, and VoiceOver.
- **RU:** Ранний прототип не следует называть готовым продуктом до прохождения обязательных P0/P1-критериев и проверки на целевой macOS.
- **EN:** Do not describe an early prototype as a finished product until mandatory P0/P1 criteria and target-macOS acceptance have passed.
