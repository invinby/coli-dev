# 11. Обратная связь и критерии готовности / Feedback and acceptance criteria

Этот список собирает правки, переданные командой 8 октября 2026 года. Он задаёт порядок исправления прототипа и критерии, по которым можно принять работу. Планы, проверки кода, сборка и ручная проверка на Mac считаются разными уровнями готовности.

This list records the team's feedback received on 8 October 2026. It sets the prototype-fix order and acceptance criteria. Plans, code checks, builds, and hands-on Mac review count as separate levels of readiness.

## Уточнение по предмету «Биология» / Clarification about Biology

**RU:** Последняя поправка команды отменяет прежнюю трактовку, будто нужно создавать биологию заново или добавлять её как новый встроенный предмет. Биология уже входит в стандартный каталог. Требование — дать ученику возможность самому создать новый предмет и добавлять темы и подтемы как в пользовательские, так и в существующие предметы. Общая проверка навигации по встроенным урокам остаётся нужна, но отдельный дефект открытия биологии не считать подтверждённым без воспроизведения.

**EN:** The team's latest clarification supersedes the earlier interpretation that Biology should be created again or added as a new built-in subject. Biology is already in the standard catalog. The requirement is to let learners create new subjects and add topics and subtopics to both custom and existing subjects. General navigation checks for built-in lessons still apply, but do not treat a Biology-specific opening bug as confirmed unless it is reproduced.

## Уточнение о продуктовом промпте / Clarification about the product prompt

**RU:** Большой промпт из командной записи — техническое задание на проектирование и разработку самого образовательного приложения: его интерфейса, архитектуры, учебных маршрутов, персонализации, источников, визуализаций и проверяемых переходов. Это не системная инструкция для отдельного AI-тьютора. Тьютор — один из компонентов продукта. Новые элементы добавлять поэтапно, исходя из пользы для обучения; сначала исправлять P0, а не выдавать запланированные функции за готовые.

**EN:** The long prompt in the team transcript is a specification for designing and building the educational application itself: its interface, architecture, learning paths, personalization, sources, visualizations, and verifiable navigation. It is not a system prompt for a standalone AI tutor. The tutor is one component of the product. Add further elements incrementally according to their learning value; fix P0 failures first and do not present planned features as complete.

## Рекомендуемый цикл занятия / Recommended lesson loop

**RU:** Диагностика → короткая цель → объяснение подходящей глубины → визуальное исследование → пример → самостоятельная практика → усложнение по результату → разбор ошибки → проверка переноса в новую задачу → фиксация выполненного → следующий шаг или повторение. Порядок меняется под предмет и состояние ученика, это не обязательный одинаковый шаблон.

**EN:** Diagnosis → a short goal → level-appropriate explanation → visual exploration → example → independent practice → result-based challenge → error analysis → transfer to a new task → record what was completed → next step or review. Adapt the order to the subject and learner; do not apply one rigid template.

## Ограничения и честная готовность / Limits and honest readiness

- **RU:** Индекс RAG и дата проверки источника не гарантируют, что текст урока автоматически обновился. Любое обновление содержания требует проверки редактором и фиксации источника.
- **EN:** An RAG index and source-check date do not mean lesson text was automatically updated. Content changes require editorial review and a recorded source.
- **RU:** Локальный API, готовый провайдер и реально ответившая модель — три разных состояния. Интерфейс и диагностика должны различать их.
- **EN:** A local API, a configured provider, and a model that actually answered are three different states. The UI and diagnostics must distinguish them.
- **RU:** Кодовая проверка Swift-модели не заменяет Xcode-сборку; Xcode-сборка не заменяет ручную проверку навигации, отображения, клавиатуры и VoiceOver на Mac.
- **EN:** A Swift model check does not replace an Xcode build. An Xcode build does not replace hands-on Mac review of navigation, rendering, keyboard access, and VoiceOver.
- **RU:** Ранний прототип не следует называть готовым продуктом до прохождения обязательных P0/P1-критериев и проверки на целевой macOS.
- **EN:** Do not describe an early prototype as a finished product until mandatory P0/P1 criteria and target-macOS acceptance have passed.

## Интерфейс и честные состояния продукта / Interface and truthful product states

**RU:** Главный экран должен давать понятный вход в предметы, сохранять действие «Продолжить обучение», показывать прогресс завершения курса отдельно от уровня освоения знаний и предлагать следующий шаг с коротким объяснением. Если уровень освоения ещё не подтверждён достаточными заданиями, так и написать — не заменять его выдуманным процентом знаний.

**EN:** The home screen should provide clear access to subjects, preserve the “Continue learning” action, show course-completion progress separately from knowledge mastery, and recommend the next step with a short reason. If mastery has not been established through enough evidence, say so instead of showing an invented knowledge percentage.

**RU:** Переходы проверять целиком: предмет → карта тем → урок → упражнение/визуализация → обратная связь → сохранённый прогресс → следующий шаг. Проверить все встроенные предметы и пользовательские темы; если ресурс действительно отсутствует, показать понятное восстановимое состояние с названием предмета и доступным действием.

**EN:** Check complete routes: subject → topic map → lesson → exercise or visualization → feedback → saved progress → next step. Cover every built-in subject and learner-created topic; if a resource is genuinely missing, show a useful recoverable state naming the subject and available next action.

**RU:** В настройках раздельно показывать доступность локального backend, Ollama, установленной модели, выбранного маршрута и фактического ответа модели. Одно зелёное состояние не должно скрывать, что следующий уровень подключения не проверен. Любой новый учебный блок (симуляция, 3D, видео, RAG-источник или AI-инструмент) получает отдельные статусы готовности и ограничения.

**EN:** Settings should report the local backend, Ollama, installed model, selected route, and an actual model reply as separate availability states. A green status must not hide that the next connection layer is unverified. Every new learning block (simulation, 3D, video, RAG source, or AI tool) needs its own readiness state and limitations.

## Диагностика реального ответа тьютора / Real tutor reply diagnostic

**RU:** В настройках добавляется отдельная проверка реального ответа по выбранному режиму «Авто» или «Только локально». Она отправляет короткий статический запрос через тот же `/chat/stream`, которым пользуется тьютор, и показывает провайдера, модель, длительность, фактический текст ответа или ошибку. Новый флаг `skip_retrieval` выключает поиск по материалам курса, заметкам Obsidian и официальным источникам для этой проверки; веб-поиск также отключён. Успех фиксируется только после непустого ответа. Проверка может расходовать лимит активного провайдера; платные маршруты по-прежнему ограничены отдельной настройкой расходов. Код и backend-тест добавлены, но реальный ответ на Mac ещё нужно проверить кнопкой в настройках.

**EN:** Settings add a real-reply check for the selected Auto or Local only mode. It sends a short static request through the same `/chat/stream` endpoint used by the tutor, then displays the provider, model, duration, actual answer text, or error. The new `skip_retrieval` flag disables retrieval from course materials, Obsidian notes, and official sources for this check; web search is also disabled. The check is successful only after a non-empty reply. It may use the active provider's quota; paid routes remain controlled by the separate cost setting. The code and backend regression test are in place, but a real Mac response still needs to be checked with the settings button.
