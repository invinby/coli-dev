# 11. Обратная связь и критерии готовности / Feedback and acceptance criteria

Этот список собирает правки, переданные командой 8 октября 2026 года. Он задаёт порядок исправления прототипа и критерии, по которым можно принять работу. Планы, проверки кода, сборка и ручная проверка на Mac считаются разными уровнями готовности.

This list records the team's feedback received on 8 October 2026. It sets the prototype-fix order and acceptance criteria. Plans, code checks, builds, and hands-on Mac review count as separate levels of readiness.

## Уточнение по предмету «Биология» / Clarification about Biology

**RU:** Последняя поправка команды отменяет прежнюю трактовку, будто нужно создавать биологию заново или добавлять её как новый встроенный предмет. Биология уже входит в стандартный каталог. Требование — дать ученику возможность самому создать новый предмет и добавлять темы и подтемы как в пользовательские, так и в существующие предметы. Общая проверка навигации по встроенным урокам остаётся нужна, но отдельный дефект открытия биологии не считать подтверждённым без воспроизведения.

**EN:** The team's latest clarification supersedes the earlier interpretation that Biology should be created again or added as a new built-in subject. Biology is already in the standard catalog. The requirement is to let learners create new subjects and add topics and subtopics to both custom and existing subjects. General navigation checks for built-in lessons still apply, but do not treat a Biology-specific opening bug as confirmed unless it is reproduced.

## Уточнение о продуктовом промпте / Clarification about the product prompt

**RU:** Большой промпт из командной записи — техническое задание на проектирование и разработку самого образовательного приложения: его интерфейса, архитектуры, учебных маршрутов, персонализации, источников, визуализаций и проверяемых переходов. Это не системная инструкция для отдельного AI-тьютора. Тьютор — один из компонентов продукта. Новые элементы добавлять поэтапно, исходя из пользы для обучения; сначала исправлять P0, а не выдавать запланированные функции за готовые.

**EN:** The long prompt in the team transcript is a specification for designing and building the educational application itself: its interface, architecture, learning paths, personalization, sources, visualizations, and verifiable navigation. It is not a system prompt for a standalone AI tutor. The tutor is one component of the product. Add further elements incrementally according to their learning value; fix P0 failures first and do not present planned features as complete.

## Пользовательская программа и визуальное покрытие / Learner curriculum and visual coverage

**RU:** Приёмка должна подтвердить, что в каталоге и на карте тем есть понятная кнопка «+»: ученик может создать собственный предмет и дерево тем/подтем, а также добавить тему во встроенный предмет, включая биологию. Биология остаётся одной встроенной дисциплиной и не дублируется. Прототип сохраняет двуязычную структуру, цели, заметки и локальный прогресс. Черновик плана из чата разбирается только по версионируемой JSON-схеме: ученик может просмотреть, изменить или удалить пункты до явного подтверждения; сохранение дерева под текущей темой должно быть атомарным. Проверяющий сценарий покрывает русско-английские поля, версии формата, уровни, повторы, размер и вложенность. Это не проверяет достоверность цитат или научных утверждений — их нужно сверять вручную. Ручная приёмка создания через «+», сохранения после перезапуска, переходов и редактирования на Mac остаётся открытой.

**EN:** Acceptance must confirm that the catalog and topic map expose a clear “+” action: learners can create a custom subject and topic/subtopic tree, and add a topic to a built-in subject, including Biology. Biology remains a single built-in discipline and is not duplicated. The prototype saves bilingual structure, goals, notes, and local progress. A chat-generated outline is parsed only through a versioned JSON schema: the learner can review, edit, or remove items before explicit approval; saving the tree beneath the current topic must be atomic. The verifier covers bilingual fields, schema versions, levels, duplicates, response size, and nesting depth. It does not verify citations or scientific claims; those still need human review. Hands-on Mac acceptance of “+” creation, persistence after relaunch, navigation, and editing remains open.

**RU:** Вести покрытие визуализациями отдельно по предметам и темам. Большинство основных тем должно иметь работающую и полезную визуальную поддержку, выбранную по содержанию: 3D там, где нужно пространственное исследование, и график, схема, опыт, видео или другая интерактивность там, где они полезнее. Для каждого модуля проверять связь с учебной целью, источник и права, доступность, текстовую альтернативу, допущения и ограничения. Пустая карточка или статичная декорация не считается визуализацией.

**EN:** Track visualization coverage by subject and topic. Most core topics should have a working, useful visual aid chosen for the content: 3D when spatial inspection matters, and a graph, diagram, experiment, video, or other interaction when that is more useful. For each module, check its learning goal, source and rights, accessibility, text alternative, assumptions, and limits. An empty card or static decoration does not count as a visualization.

## Самооценка типа ошибки / Learner-reported error type

**RU:** После неправильного ответа ученик может по желанию отметить, что именно ему помешало: понимание, память, применение, внимание к условию, логика, базовые знания или выбор метода. Перед повторной попыткой приложение предлагает короткую стратегию для выбранного типа. Отметка сохраняется с локальным прогрессом и показывается как самооценка по последним проверкам; она не является автоматическим диагнозом и сама по себе не доказывает освоение темы. Пропуск доступен всегда. Следующий этап — связать накопленные сигналы с конкретными предпосылками и учебными заданиями, не делая выводов из одной ошибки.

**EN:** After a wrong answer, learners may optionally report what got in the way: understanding, memory, application, attention to the prompt, reasoning, prerequisite knowledge, or method choice. Before retrying, the app offers a short strategy for the selected category. The report is stored with local progress and shown as self-reported difficulty from recent checks; it is not an automated diagnosis and does not by itself prove mastery. Skipping is always allowed. The next step is to connect accumulated signals to explicit prerequisites and learning activities without drawing conclusions from one mistake.

**Статус внедрения / Implementation status — 2026-10-08:** после неправильного ответа добавлен необязательный выбор категории и двуязычная подсказка к повтору. Неудачная и успешная попытки сохраняются отдельными событиями с явным признаком результата; неудачная проверка не открывает следующий уровень. Категории ошибок агрегируются по истории попыток, проходят проверку, попадают в резервную копию и показываются на главном экране как число тем с такой самооценкой. GitHub Actions [37753036863](https://github.com/invinby/coli-dev/actions/runs/37753036863) прошёл backend suite, все Swift-verifier'ы и сборки с упаковкой для Apple Silicon и Intel. Ручной просмотр на Mac и реальный цикл «ошибка → повтор → отметка на главном экране» ещё нужно выполнить. Следующий шаг — проверить этот сценарий на Mac и затем связывать повторяющиеся самоотчёты с явными предпосылками и заданиями.

**Implementation status / Статус внедрения — 2026-10-08:** the optional error-category choice and bilingual retry strategy are now shown after a wrong answer. Failed and successful attempts are stored as separate events with an explicit outcome; a failed check cannot unlock the next level. Error categories are aggregated across attempts, validated, included in backups, and shown on the dashboard as a count of topics with that self-report. GitHub Actions [37753036863](https://github.com/invinby/coli-dev/actions/runs/37753036863) passed the backend suite, every Swift verifier, and packaged builds for Apple Silicon and Intel. A hands-on Mac review and the real “wrong answer → retry → dashboard” flow remain to be checked. Next, verify this flow on a Mac, then connect repeated self-reports to explicit prerequisites and practice activities.

### Рекомендация по повторяющейся самооценке / Recommendation from repeated self-reports

**RU:** Когда одна и та же категория самооценки указана минимум в двух проверках по теме, а последняя проверка знаний по этой теме явно не пройдена и содержит ту же отметку, главная может предложить повторить именно эту тему и показать соответствующую двуязычную стратегию. Более свежая успешно пройденная проверка снимает этот приоритет. Одной ошибки недостаточно; это учебная подсказка по выбору самого ученика, не диагноз. Обычное продолжение незавершённого урока и просроченные повторы сохраняют приоритет.

**EN:** When the same self-reported category appears in at least two checks for a topic, and the latest knowledge check for that topic is explicitly failed and carries the same report, the dashboard may recommend that topic with the matching bilingual review strategy. A later passed check removes this priority. One mistake is not enough; this is a study suggestion based on the learner's own report, not a diagnosis. Resuming an unfinished lesson and due reviews retain priority.

**Статус внедрения / Implementation status — 2026-10-08:** алгоритм и RU/EN-подсказка добавлены; Swift-verifier покрывает приоритет повторяющегося сигнала над общим числом повторов и снятие рекомендации после успешной проверки. GitHub Actions [37753036863](https://github.com/invinby/coli-dev/actions/runs/37753036863) прошёл backend-проверки и сборки macOS для Apple Silicon и Intel.

**Implementation status / Статус внедрения — 2026-10-08:** the selector and RU/EN guidance are implemented; the Swift verifier covers prioritizing a repeated report over a generic retry count and clearing that priority after a passed check. GitHub Actions [37753036863](https://github.com/invinby/coli-dev/actions/runs/37753036863) passed the backend checks and Apple Silicon and Intel macOS builds.
