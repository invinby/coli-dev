# 04. ИИ, агенты и RAG

## Подтверждённые требования пользователя

- ИИ должен работать в онлайн- и офлайн-режимах.
- Для сложных общих запросов нужна сильная главная модель.
- Для предметных задач должны подбираться специализированные модели/агенты.
- Локальные и более лёгкие модели нужны для задач, где не требуется облачная мощность.
- Несколько агентов могут собирать и проверять результат, а главная модель формирует единый ответ.
- RAG нужен для актуальных тем и данных, чтобы ответы не опирались только на устаревающую память модели.
- Желательны мощные модели с большими бесплатными лимитами; реальные условия необходимо проверять и показывать.

## Целевая схема RAG

1. Источники: проверенные курсы, пользовательский Obsidian vault и разрешённые обновляемые внешние источники.
2. Индексация: извлечение, разбиение на фрагменты, метаданные, язык, ссылка, дата публикации/обновления и дата последней проверки.
3. Поиск: отбор фрагментов по курсу, теме, языку, свежести и релевантности.
4. Ответ: модель получает вопрос и выбранные материалы; показывает ссылки/цитаты и дату данных.
5. Офлайн: использовать локальные материалы и сохранённый индекс, явно показывая дату последней синхронизации и ограничения свежести.
6. Обновление: контролируемая синхронизация, обнаружение изменений, повторная индексация и журнал источников.

### Реализованный срез автоматической свежести — 2026-10-06

- Фоновая проверка официальных URL сохраняет ограниченный локальный snapshot и подключает свежие фрагменты к обычному course/Obsidian retrieval для трёх узких семейств: Python Tutorial под PSF License Version 2, точных MedlinePlus Genetics страниц `basics/dna` и `basics/gene` из public-domain Genetics summaries и точной NIST SI Appendix B.9 страницы, distributable/copyable по общим условиям NIST, если не помечена copyrighted. В snapshot записываются canonical URL, дата успешной проверки, digest, лицензия, ссылка на условия и обязательная атрибуция; поиск передаёт модели фрагмент и citation URL.
- Автоматически допускаются только URL из уже проверенных Markdown-ссылок текущих уроков, совпадающие с allowlist пути `/3/tutorial/*.html`. Retrieval отбрасывает снимок старше 48 часов или источник со статусом ошибки; запускаемый backend обновляет страницы примерно раз в сутки, 304 продлевает срок валидированного неизменённого снимка. Два лучших источника на запрос и выдержка до 1 400 символов ограничивают контекст.
- В Control Center реестр различает лицензированный кешированный текст, ожидание первой проверки и metadata-only. OpenStax, British Council, Animal Diversity Web и произвольные ссылки не попадают текстом в web-RAG. Изменение сайта обновляет только локальный snapshot и не перепубликует авторский урок.
- Это ещё не обще-предметный web-RAG и не проверка фактов: правила разрешённого текстового кэша пока определены только для двух узких семейств источников. Точность фрагментирования, полнота официальных источников по всем предметам и фактические ответы на Mac требуют дальнейшей проверки.

## Оркестрация агентов

- Главный оркестратор решает, достаточно ли одной модели или нужны поиск/специалист/проверка.
- Специалистам выдаются короткие ограниченные задачи и только нужный контекст.
- Критик проверяет факты, выводы и полноту; финальный ответ остаётся единым и понятным.
- Ограничить число агентов, время, токены и стоимость на один запрос.
- Если квота провайдера исчерпана, переключаться на разрешённый запасной вариант или локальную модель и сообщать об этом.
- Не запускать коллективный спор моделей на каждый простой вопрос.

## Выбор моделей и провайдеров

OpenRouter и Ollama упомянуты пользователем как варианты. Перед реализацией проверить актуальные модели, права использования, бесплатные лимиты, контекст, доступность из региона, приватность и совместимость API. Не строить систему на одном бесплатном лимите.

### Отдельные локальные модели ролей Auto — 2026-10-06

- Control Center позволяет выбрать отдельный Ollama model ID для локального черновика, критика и независимого проверяющего. Все три роли используют только проверенный loopback Ollama; настройки не включают облачные вызовы и не обходят глобальную защиту платных маршрутов.
- Preferences хранятся отдельно от ключей в локальном файле настроек; значение по умолчанию для каждой роли — `OLLAMA_MODEL_RESEARCHER`. ID проверяется по ограниченному формату. Установленные модели можно выбрать из каталога, получаемого только с loopback Ollama; в каталог передаются только валидированные имена моделей, не теги с метаданными/размерами и не секреты. Ручной ID также допустим; если модели нет на диске Ollama, она обнаружится только при вызове.
- Подключены loopback-only GET/PUT/DELETE endpoints для ролей и loopback-only инвентарь установленных моделей, плюс SwiftUI-клиент на RU/EN. Тесты подтверждают, что именно выбранный model ID передаётся локальному вызову и что API не меняет ни провайдера, ни privacy-маршрут роли.
- Облачные модели критика/verifier и полный редактор всех ролей ещё не настраиваются; их подключение потребует явной передачи контекста в облако, применения cost gate и отдельного отображения фактически использованного маршрута.

### Проверка OpenRouter — 2026-10-05

- Официальный API совместим с OpenAI Chat Completions через `https://openrouter.ai/api/v1/chat/completions`; API key передаётся как Bearer token. Это позволяет добавить provider без отдельного SDK.
- Официальный маршрут `openrouter/free` бесплатно выбирает случайную модель из доступного набора free-моделей; состав и выбранная модель меняются, значит качество/возможности не гарантированы постоянными. FAQ отмечает низкие rate limits для free-моделей. Поэтому это разумный добровольный резервный маршрут, но нельзя обещать постоянный топовый движок или большой стабильный бесплатный лимит.
- Перед включением в Auto: сохранить ключ через существующий Keychain API; сделать fallback явным и ограниченным; показать выбранную модель, источник ответа и статус лимита/стоимости; проверить privacy/provider logging. Документация: [Quickstart](https://openrouter.ai/docs/quickstart), [Free Models Router](https://openrouter.ai/openrouter/free/apps), [FAQ: free tiers](https://openrouter.ai/docs/faq).

### Backend fallback implementation — 2026-10-05

- Добавлен `openrouter` в whitelist секретов: macOS Keychain и `.env` fallback. UI позволяет сохранить его ключ и показывает настроенный маршрут из `/health`; по умолчанию `OPENROUTER_MODEL=openrouter/free`, а модель можно задать backend environment.
- Если пользователь явно разрешает платные маршруты, оркестратор параллельно собирает черновики Gemini Flash, настроенного предметного провайдера и Ollama; локальные модели проверяют черновики, а финальный этап по умолчанию использует Gemini 3.1 Pro Preview. По умолчанию действует отдельная free-only политика, описанная ниже.
- Ответы OpenRouter обрабатываются по тем же ограничениям request timeout/`max_tokens`, API key не уходит в UI, endpoint не настраивается пользователем. Настройки предупреждают, что доступность free-моделей и лимиты меняются, а платная model ID может взимать оплату.
- Актуальная таблица тарифов Gemini API помечает free tier для Gemini 3.1 Pro Preview как недоступный; в Auto интерфейс теперь предупреждает о возможной платной квоте. Это не live-оценка стоимости конкретного запроса, а предупреждение о тарифе модели. См. [официальную таблицу тарифов](https://ai.google.dev/gemini-api/docs/pricing) и [карточку модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-pro-preview).
- Настройки показывают настроенный router ID; после ответа SSE-подпись показывает model ID, который вернул OpenRouter. Если API его не вернул, подпись указывает настроенный маршрут и явно пишет, что разрешённое имя модели неизвестно. Это заявленное API-полем имя, не независимая проверка провайдера. В текущей рабочей копии добавлен ручной выбор провайдера/model ID specialist-слота по каждому предмету; настройка не редактирует остальные роли консилиума. Отображение фактических лимитов/стоимости и полноценная live-проверка ключа/модели ещё нужны. Free fallback не считается гарантированно бесплатным или постоянно доступным.

### Настраиваемый финальный синтез — 2026-10-06

- Control Center позволяет настроить provider/model ID именно финальной роли Auto: Automatic, Gemini, Kimi, OpenRouter или Ollama. Значение хранится локально отдельно от ключей. При разрешённых платных маршрутах Automatic использует Gemini Pro; free-only режим переопределяет Automatic на OpenRouter Free при заданном ключе или на локальный Ollama.
- Изменённый облачный маршрут при ошибке не переключается на другой облачный provider: финальный ответ использует локальный Ollama fallback, а выбранный и фактически использованный provider/model ID попадают в подпись ответа. Выбор Ollama ограничивается loopback endpoint.
- Эта настройка не меняет предметный specialist-слот черновика и не управляет критиком/verifier. Защита расходов Auto по умолчанию блокирует прямые Gemini/Kimi и платные model ID; выбор `openrouter/free` разрешён. Режим «Только локально» по-прежнему нужен, если вопрос не должен покидать Mac.
- Backend API и оркестратор покрыты тестами; GitHub Actions run [37381727625](https://github.com/invinby/coli-dev/actions/runs/37381727625) подтвердил Xcode build, backend packaging и smoke-test для Apple Silicon и Intel. Реальный запуск UI на Mac и доступность внешней модели/Ollama зависят от пользовательского Mac, API ключа, model ID и установленного сервиса.

### Предметно-нейтральные рубрики Auto-консилиума — 2026-10-05

- Judge, критик и локальный verifier больше не считают, что каждый запрос про архитектуру ПО и Python. Они проверяют точность по предмету, логические шаги, соответствие контексту урока и уровню ученика, ясность, примеры, ограничения и неопределённость.
- Рубрики и финальный синтез формулируются на языке интерфейса RU/EN. Проверки синтаксиса, безопасности и производительности кода применяются только когда в задаче действительно есть код; `[K#]` citations сохраняются и не должны выдумываться.
- Автосохранение краткой заметки больше не создаёт пустую фоновую задачу, если локальный Obsidian bridge не настроен.
- Предметная настройка модели специалиста подключена к локальной панели: для шести направлений можно задать Gemini, Kimi, OpenRouter или Ollama либо вернуть общий автоматический выбор. Она управляет слотом специалиста в Auto-черновиках; финальный синтез и проверка остаются в общей цепочке.
- Секреты в маршруте не хранятся. Backend показывает наличие ключа/локального endpoint, но валидность model ID проверяется первым запросом. При отказе настроенного провайдера он исключается из fallback-попытки, а фактически использованные модели добавляются в подпись ответа и учёт usage.
- Полный каталог моделей, автоматическая проверка лимитов/цен, управление бюджетом и редактор всей многоагентной схемы остаются отдельными задачами. Нельзя объявлять модель бесплатной или «лучшей» без проверки условий и актуальности.

### Проверочные рубрики шести предметов — 2026-10-05

- Нативный клиент передаёт одно из шести фиксированных значений `subject`; Pydantic отклоняет произвольные темы. Backward-compatible API-запросы без поля сохраняют прежнее поведение.
- Backend добавляет RU/EN рубрику в системный контекст для Auto, локального и отдельного Google-grounded маршрута. Проверки предметные: шаги/условия в математике, смысл и регистр в английском, единицы и допущения в физике, модель и вероятности в биологии, поколения/экология в зоологии, версия языка/edge cases/непритворное выполнение кода в программировании.
- Предметная рубрика по-прежнему действует для всей цепочки, но specialist-слот Auto теперь можно отдельно маршрутизировать по каждому предмету; остальные роли используют общие настройки и не имеют per-agent редактора.

### Локальный учёт provider-reported tokens — 2026-10-05

- Ответы Gemini, Kimi, OpenRouter и Ollama сохраняют в отдельную SQLite-базу только модельные метаданные и upstream usage counters; в записях нет промптов, ответов или API-ключей. Потоковые Gemini/Ollama учитываются по финальным метаданным события.
- Loopback `GET /api/usage` агрегирует до 90 дней; настройки показывают последние 30 дней. Отсутствующие значения остаются неизвестными, стоимость не вычисляется.
- Это прозрачность usage, а не фактическая квота или платёжный лимит. Реальное ограничение бюджета, учёт актуальных тарифов и отображение пользовательских лимитов остаются отдельной задачей.

## Implemented local retrieval slice — 2026-10-04

- Added an incremental SQLite index in `01_Projects/knowledge_index.py`. It scans Markdown under `02_Areas/` and Markdown/text under `03_Resources/Cheatsheets/`; it excludes hidden paths, symlinks, plans, prompts, and other roots. The lexical path needs no model or network service.
- For each tutor query, the backend hashes and refreshes changed source files, chunks Markdown with heading/line metadata, and ranks relevant chunks with bounded BM25-style lexical scoring. It stores the cache in the per-user application-data directory and works without network access.
- Local course hits are interleaved with live Obsidian hits; up to four excerpts receive `[K#]` citations. The app displays repository path, line span, retrieval time, and available filesystem modification time. Obsidian modification time remains unavailable.
- `/health` reports indexed-document count and last index check. The app displays both in Settings. Auto-mode privacy copy now includes course and Obsidian snippets.
- The local `02_Areas/` corpus now includes six bilingual curriculum roadmaps for the priority subjects, so the offline index can retrieve the intended sequence and advanced-topic coverage. These outlines do not substitute for verified lesson content; `03_Resources/Cheatsheets/` is not populated yet.
- Added optional Ollama `/api/embed` hybrid retrieval, enabled only when `OLLAMA_EMBEDDING_MODEL` is set and `OLLAMA_URL` resolves to a loopback URL. Document vectors are cached by chunk and model in SQLite; query and document vectors are normalized and combined with lexical ranks using reciprocal-rank fusion. Similarity below 0.25 is excluded; embedding errors fall back to lexical search and pause retries for one minute to avoid stalling each request. Ollama calls bypass system proxies and redirects. Mock tests cover semantic matching, caching, loopback enforcement, request shape, and offline fallback; retrieval quality and latency with a real model remain unverified.
- `/health` reports the configured embedding model name (never a secret), and the SwiftUI Settings view distinguishes a configured local semantic route from keyword-only retrieval. It reports configuration, not proof that the Ollama embedding model is installed or responsive.
- This still does not provide broad web-RAG, source authority/licensing checks, publication dates, or factual verification. File modification time is not an accuracy guarantee.

## Opt-in Google Search grounding — 2026-10-05

- Auto mode can route an explicitly selected current question and its lesson context directly to Gemini with Google's `google_search` tool. The response is returned with inline source links and the required Search Suggestions HTML.
- The feature requires explicit 18+ confirmation before the first search in a chat view. This is a UI attestation, not an account-age verification system; intended audience eligibility remains a release blocker.
- Google's current Gemini API terms also limit API use to professional or business purposes and impose region restrictions. Confirm the product's audience, purpose, and supported regions before distribution.
- The UI explains that Google stores prompts, context, and results for up to 30 days. Under unpaid Gemini API quota, Google may use prompts and responses to improve its services and human reviewers may process them; learners are told not to submit sensitive data.
- By default, this path bypasses local retrieval, agent debate, and Obsidian saving. A second, explicit opt-in can retrieve up to four local course/Obsidian excerpts; those excerpts are JSON data in the learner message, not system instructions, and appear as `[K#]` sources alongside Google's numbered web citations. The UI warns that selected local excerpts will be sent to Gemini/Google. Earlier grounded answers are not forwarded in later model prompts.
- The API response is accepted only when it has valid public HTTP(S) sources and Search Suggestions. This is still not a general indexed web-RAG system: it does not apply per-subject source allowlists, persistent web indexing/freshness policy, or fact-check review. Combining web and local sources is limited to one explicitly requested search.
- Backend tests cover source URL filtering, citation insertion, malformed metadata, direct routing, age/key/quota guards, and refusal in Local/offline mode. The live Google API, account quota/billing, and visual behavior on a user's Mac remain unverified.

## Source-reference review metadata — 2026-10-05

- Markdown frontmatter may contain one strict `source_checked: YYYY-MM-DD` field. The local course index validates the calendar date and returns it as `source_checked_at`, separately from filesystem `modified_at` and retrieval time.
- Frontmatter is not copied into indexed excerpts; citation text keeps its original file line numbers. The backend migrates older SQLite indexes in place by adding a nullable date column.
- The RAG prompt and SwiftUI source card explain that this is author-supplied note metadata, not independent factual verification or proof that the underlying information is current. Obsidian and web sources do not receive this metadata.
- Automated trust rankings, publication-date discovery, staleness policy, and source refresh are still open work; this slice only makes declared source-review dates visible and correctly qualified.

### Optional author-scheduled review reminder — 2026-10-05

- Markdown notes may also declare one integer `source_review_interval_days` from 1 through 3650. When both this field and `source_checked` are valid, the index calculates a reminder date and reports whether that date has arrived.
- The cadence is chosen by the note author. A reached date is shown in the RU/EN source card and prompt as a reminder to re-check, never as evidence that the material is stale or that ColiDev verified it.
- Existing SQLite indexes gain a nullable cadence column in place. Missing, duplicate, nested, malformed, zero, or over-limit values are ignored; frontmatter stays out of the retrieved excerpt and citation line numbers remain tied to the source file.
- This improves review tracking only. It does not fetch sources, inspect publication dates, or provide automatic freshness verification.
- `/health` and macOS Settings summarize indexed materials whose author review date is due, whose schedule is still upcoming, or whose review schedule is missing. Older indexes receive the additive columns when health reports status; the reminder is explicitly labeled as author-declared and does not claim that the app validated current facts.

### Citation marker validation — 2026-10-05

- Before the answer is streamed, the backend checks each `[K#]` marker against the local course/Obsidian source IDs attached to that response. A marker with no matching retrieved source is replaced with a localized unavailable-source note, and its ID is included in SSE `done.citation_warnings`.
- The SwiftUI tutor displays the warning and states that this only checks the source ID exists; it does not verify that the source supports the claim. Inline and fenced Markdown code are preserved to avoid rewriting code examples.
- This is structural validation only. It does not test claim-to-evidence entailment, source authority, or factual correctness; Google Search's numbered citations continue to rely on Google's grounding metadata.

### Пользовательский OpenAI-compatible провайдер — 2026-10-06

- Control Center сохраняет базовый HTTPS URL (HTTP допускается только для loopback), точный model ID и API key отдельно; ключ хранится через существующий Keychain provider-secret API, endpoint/model — в локальном JSON с ограниченными правами.
- Custom route доступен для предметного специалиста и финального синтезатора. Он относится к потенциально платным и не вызывается Auto при выключенной защите расходов; тогда используется Ollama. Использование сохраняет только metadata usage, если провайдер её сообщил.
- Интерфейс показывает, что endpoint/model/key настроены, но не обещает сетевую доступность до реального вызова. Начальная версия использовала буферный запрос; текущее состояние потока OpenAI-compatible указано ниже.

### Нативный стриминг финального ответа OpenAI-compatible и выбранной Ollama-модели — 2026-10-06

- Финальный Auto теперь передаёт SSE `delta.content` от настроенного OpenAI-compatible endpoint и NDJSON-чанки выбранной финальной модели Ollama непосредственно в SSE чата. Промежуточные черновики, критик и проверяющий по-прежнему остаются скрыты от ученика; стримится только финальный синтез.
- Custom API сохраняет существующие ограничения: удалённый endpoint требует HTTPS, loopback HTTP остаётся локальным, облачный call сначала резервируется в дневном бюджете, API key не возвращается/не логируется, usage записывается только если провайдер прислал счётчики. Если поток оборвался после видимого текста, ответ явно помечается как неполный, вместо приписывания отдельного локального ответа к уже показанному тексту.
- Ollama теперь использует точный model ID финального маршрута и сообщает usage из завершающего NDJSON-события. При отсутствии callback/streaming используются прежние обычные HTTP-запросы.
- Mock-тесты проверяют инкрементальный SSE, headers/model ID, usage, выбранную custom/Ollama модель и обработку обрыва; live сторонний endpoint и пользовательская модель Ollama не проверялись.

### Потоковый финал OpenRouter — 2026-10-06

- Финальный Auto-ответ OpenRouter теперь проходит тем же SSE-парсером, что и пользовательский OpenAI-compatible endpoint; настроенный/разрешённый model ID, отдельный OpenRouter API key, дневной cloud budget и учёт provider usage сохраняются. В запрос добавлены рекомендованные OpenRouter идентификаторы приложения.
- Черновики и критические роли остаются скрытыми; незавершённый поток после первого чанка помечается как неполный. [Официальная документация OpenRouter](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request?explorer=true) подтверждает `stream: true` и `choices[].delta.content`; mock-проверки покрывают разбор чанков, заголовки, budget и usage. Live OpenRouter key/model и пользовательский Mac не проверялись.

## Реализация клиента — 2026-10-04

- Добавлены RU/EN и auto/local поля в POST /chat/stream; старые клиенты без них сохраняют русский язык и автоматический маршрут по умолчанию.
- SwiftUI-тьютор использует GET /health и SSE POST /chat/stream существующего локального оркестратора, отправляет контекст текущего урока и недавнюю историю диалога, показывает SSE-ответ по частям и позволяет прервать приём. Backend отправляет начальные SSE-байты до вызова провайдеров, а отключение клиента отменяет in-flight async генерацию. Local-only маршрут передаёт нативные NDJSON-чанки Ollama сразу через SSE; после завершения `done.answer` содержит ответ с проверенными RAG-цитатами, и SwiftUI заменяет им временный текст потока. Auto сначала собирает черновики и локальную критику, затем нативно стримит только финальный текст Gemini Pro через `streamGenerateContent?alt=sse`; промежуточные агентские черновики и части с `thought: true` ученику не показываются. Direct Google Search тоже стримит текст провайдера нативно, собирает incremental grounding metadata и проверяет наличие источников/Search Suggestions перед финальным событием. Для всех маршрутов `done.answer` остаётся проверенной финальной версией; при полном отказе Gemini Auto включает локальный фолбек, а не завершённый ответ не выдаётся как полный. Состояние авто-маршрута учитывает доступность облачного соединения, лимит сессий и наличие готовой Ollama-модели; сеть Ollama отдельно от облачного соединения.
- Добавлен начальный retrieval из живого Obsidian vault: приложение отправляет отдельный поисковый запрос вместе с предметом/уроком; backend передаёт найденные контекстные фрагменты в модель, просит использовать маркеры `[K#]` и возвращает пути/выдержки в SSE `done`. Каждый запрос ограничен четырьмя заметками и примерно 1.4 KB текста на заметку. В авто-режиме найденные выдержки могут уйти облачным моделям; локальный режим использует выбранный endpoint Ollama.
- Настройки предлагают автоматический и local-only маршруты. Чат блокирует local-only отправку, пока health API не подтвердит готовность Ollama-модели и loopback-адрес. Удалённые Ollama endpoints не получают запрос; Ollama-клиент не использует системные HTTP proxy. Obsidian REST разрешён только на loopback и не получает удалённые поисковые запросы. Автоматические запросы могут уйти настроенным облачным провайдерам. Gemini, Kimi и Obsidian keys можно сохранить через окно настроек в macOS Keychain; backend возвращает только configured/source, значение ключа не отдаётся. `.env` остаётся dev-fallback.
- Текущий retrieval объединяет живой Obsidian vault, автономный SQLite-индекс курсов и ограниченные лицензированные web-снимки. Курсный индекс обновляет изменившиеся файлы, разбивает Markdown на фрагменты с заголовками и номерами строк, а поиск работает офлайн лексически; при явной настройке loopback Ollama доступны кэшируемые семантические векторы и гибридное ранжирование. Python Tutorial, две MedlinePlus Genetics basics-страницы и точная NIST SI Appendix B.9 страница попадают в отдельный web-RAG при успешной проверке; другие внешние страницы пока дают только метаданные. Найденные фрагменты сериализуются как JSON в пользовательское сообщение отдельно от system prompt; система просит считать их справочными данными, а не командами. Это снижает риск prompt injection, но не исключает его и не доказывает точность утверждений. Google Search grounding остаётся отдельным прямым opt-in маршрутом. Полноценный RAG для всех дисциплин, проверка соответствия утверждениям источников и безопасное автоматическое редактирование уроков не реализованы. Backend прошёл локальную проверку; macOS CI и ручное поведение на Mac требуют свежей сборки после публикации.
