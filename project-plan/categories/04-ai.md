# 04. ИИ, агенты и RAG

## Подтверждённые требования пользователя

- ИИ должен работать в онлайн- и офлайн-режимах.
- Для сложных общих запросов нужна сильная главная модель.
- Для предметных задач должны подбираться специализированные модели/агенты.
- Локальные и более лёгкие модели нужны для задач, где не требуется облачная мощность.
- Несколько агентов могут собирать и проверять результат, а главная модель формирует единый ответ.
- RAG нужен для актуальных тем и данных, чтобы ответы не опирались только на устаревающую память модели.
- Желательны мощные модели с большими бесплатными лимитами; реальные условия необходимо проверять и показывать.

## Целевая схема RAG

1. Источники: проверенные курсы, пользовательский Obsidian vault и разрешённые обновляемые внешние источники.
2. Индексация: извлечение, разбиение на фрагменты, метаданные, язык, ссылка, дата публикации/обновления и дата последней проверки.
3. Поиск: отбор фрагментов по курсу, теме, языку, свежести и релевантности.
4. Ответ: модель получает вопрос и выбранные материалы; показывает ссылки/цитаты и дату данных.
5. Офлайн: использовать локальные материалы и сохранённый индекс, явно показывая дату последней синхронизации и ограничения свежести.
6. Обновление: контролируемая синхронизация, обнаружение изменений, повторная индексация и журнал источников.

### Реализованный срез автоматической свежести — 2026-10-06

- Фоновая проверка официальных URL сохраняет ограниченный локальный snapshot и подключает свежие фрагменты к обычному course/Obsidian retrieval только для узких разрешённых путей в четырёх семействах: страницы Python Tutorial и одну точную Python Language Reference страницу про `assert` под PSF License Version 2; точные MedlinePlus Genetics `basics/dna` и `basics/gene` из public-domain Genetics summaries; точные страницы NIST SI Appendix B.9 и Metric (SI) Prefixes при условии, что они не помечены copyrighted; и один конкретный eLife XML article под CC BY 4.0. В snapshot записываются canonical URL, дата успешной проверки, digest, лицензия, ссылка на условия и обязательная атрибуция; поиск передаёт модели фрагмент и citation URL.
- Автоматически допускаются только URL из проверенных Markdown-ссылок текущих уроков, совпадающие с точными allowlist хоста и пути для соответствующего семейства источников. Retrieval отбрасывает снимок старше 48 часов или источник со статусом ошибки; запускаемый backend обновляет страницы примерно раз в сутки, 304 продлевает срок валидированного неизменённого снимка. Два лучших источника на запрос и выдержка до 1 400 символов ограничивают контекст.
- В Control Center реестр различает лицензированный кешированный текст, ожидание первой проверки и metadata-only. OpenStax, British Council, Animal Diversity Web и произвольные ссылки не попадают текстом в web-RAG. Справка OpenStax указывает CC BY-NC-SA, а страницы книг запрещают ingest в LLM и генеративные AI-продукты без предварительного письменного разрешения; поэтому ссылки остаются видимыми, а текст не кэшируется для RAG. Изменение сайта обновляет только локальный snapshot и не перепубликует авторский урок.
- Это ещё не обще-предметный web-RAG и не проверка фактов: правила текстового кэша определены только для этих точных URL/path allowlist внутри четырёх узких семейств. Точность фрагментирования, полнота официальных источников по всем предметам и фактические ответы на Mac требуют дальнейшей проверки.

### NIST Metric (SI) Prefixes in web-RAG / Префиксы Metric (SI) от NIST в web-RAG — 2026-10-08

**RU:** В текущем уроке математики о дробях и процентах уже была ссылка на точную официальную страницу NIST [Metric (SI) Prefixes](https://www.nist.gov/pml/owm/metric-si-prefixes). Этот URL теперь включён в монитор и web-RAG по точному пути. NIST сообщает, что в SI сейчас признаются 24 префикса от 10³⁰ до 10⁻³⁰, и указывает обновление страницы 13 августа 2025 года. По [правилам NIST об авторских правах](https://www.nist.gov/copyrights-disclaimers) информация, не помеченная как copyrighted, считается общедоступной и может распространяться с указанием источника. Снимок автоматически перепроверяется примерно раз в сутки, пока работает backend; retrieval принимает его не старше 48 часов и возвращает URL, дату и атрибуцию. Добавление проверено тремя профильными тестами и GitHub Actions [37755511811](https://github.com/invinby/coli-dev/actions/runs/37755511811), где прошли 480 backend-тестов и сборки macOS для Apple Silicon и Intel. Дата проверки страницы не доказывает, что все уроки по математике и физике обновлены или проверены; реальное обновление страницы на Mac здесь не проверялось.

**EN:** The existing mathematics lesson on fractions and percentages already linked to the exact official NIST [Metric (SI) Prefixes](https://www.nist.gov/pml/owm/metric-si-prefixes) page. This exact URL is now included in monitoring and web-RAG. NIST says 24 prefixes, from 10³⁰ to 10⁻³⁰, are currently recognized in SI and lists the page as updated on 13 August 2025. Under [NIST copyright guidance](https://www.nist.gov/copyrights-disclaimers), information not marked as copyrighted is public information that may be distributed or copied with source credit. The snapshot is rechecked about once a day while the backend is running; retrieval accepts it only within 48 hours and returns its URL, date, and attribution. The addition is covered by three focused tests and GitHub Actions [37755511811](https://github.com/invinby/coli-dev/actions/runs/37755511811), where all 480 backend tests and the Apple Silicon and Intel macOS builds passed. A page check date does not prove that all mathematics and physics lessons are updated or reviewed; live page refresh on a Mac was not verified here.

### Ограничения лицензии OpenStax для AI / OpenStax license limits for AI — 2026-10-08

**RU:** Официальная справка OpenStax указывает лицензию CC BY-NC-SA для учебников и запрещает коммерческое использование без разрешения; страницы книг отдельно запрещают ingest текста в LLM или генеративные AI-сервисы без предварительного письменного разрешения. Поэтому ссылки OpenStax можно показывать как учебные источники, но текст этих страниц не загружается в web-RAG ColiDev без письменного разрешения и проверки лицензии конкретной книги.

**EN:** OpenStax's official help identifies CC BY-NC-SA as the textbook license and prohibits commercial use without permission; individual book pages separately prohibit ingesting the text into LLMs or generative AI offerings without prior written permission. ColiDev may show OpenStax links as learning references, but it does not fetch their page text into web-RAG without written permission and a license check for the specific book.

### Справедливость очереди мониторинга — 2026-10-07

- Лимит одного прохода остаётся 96 одобренных ссылок, но при превышении лимита ссылки без истории проверки и проверенные раньше остальных получают приоритет. Это не даёт URL за алфавитным хвостом навсегда выпадать из автоматического мониторинга; планировщик учитывает выбранную ротационную партию.
- Регрессионный тест строит 85 разрешённых ссылок и подтверждает, что сначала проверяются первые 80, затем 5 ранее пропущенных, после чего очередь продолжает двигать давно проверенные ссылки; также подтверждается немедленный запуск расписания для непроверенного хвоста.
- Ограничение остаётся: автопроверка обновляет статус/разрешённый snapshot источника по расписанию только пока backend запущен. Она не переписывает уроки и не гарантирует актуальность всех дисциплин; для этого нужны подходящие разрешённые источники, редакторская проверка и дальнейшее расширение точных правил кэширования.

## Оркестрация агентов

- Главный оркестратор решает, достаточно ли одной модели или нужны поиск/специалист/проверка.
- Специалистам выдаются короткие ограниченные задачи и только нужный контекст.
- Критик проверяет факты, выводы и полноту; финальный ответ остаётся единым и понятным.
- Ограничить число агентов, время, токены и стоимость на один запрос.
- Если квота провайдера исчерпана, переключаться на разрешённый запасной вариант или локальную модель и сообщать об этом.
- Не запускать коллективный спор моделей на каждый простой вопрос.

## Выбор моделей и провайдеров

OpenRouter и Ollama упомянуты пользователем как варианты. Перед реализацией проверить актуальные модели, права использования, бесплатные лимиты, контекст, доступность из региона, приватность и совместимость API. Не строить систему на одном бесплатном лимите.

### Отдельные локальные модели ролей Auto — 2026-10-06

- Control Center позволяет выбрать отдельный Ollama model ID для локального черновика, критика и независимого проверяющего. Все три роли используют только проверенный loopback Ollama; настройки не включают облачные вызовы и не обходят глобальную защиту платных маршрутов.
- Preferences хранятся отдельно от ключей в локальном файле настроек; значение по умолчанию для каждой роли — `OLLAMA_MODEL_RESEARCHER`. ID проверяется по ограниченному формату. Установленные модели можно выбрать из каталога, получаемого только с loopback Ollama; в каталог передаются только валидированные имена моделей, не теги с метаданными/размерами и не секреты. Ручной ID также допустим; если модели нет на диске Ollama, она обнаружится только при вызове.
- Подключены loopback-only GET/PUT/DELETE endpoints для ролей и loopback-only инвентарь установленных моделей, плюс SwiftUI-клиент на RU/EN. Тесты подтверждают, что именно выбранный model ID передаётся локальному вызову и что API не меняет ни провайдера, ни privacy-маршрут роли.
- Облачные модели критика/verifier и полный редактор всех ролей ещё не настраиваются; их подключение потребует явной передачи контекста в облако, применения cost gate и отдельного отображения фактически использованного маршрута.

### Проверка OpenRouter — 2026-10-05

- Официальный API совместим с OpenAI Chat Completions через `https://openrouter.ai/api/v1/chat/completions`; API key передаётся как Bearer token. Это позволяет добавить provider без отдельного SDK.
- Официальный маршрут `openrouter/free` бесплатно выбирает случайную модель из доступного набора free-моделей; состав и выбранная модель меняются, значит качество/возможности не гарантированы постоянными. FAQ отмечает низкие rate limits для free-моделей. Поэтому это разумный добровольный резервный маршрут, но нельзя обещать постоянный топовый движок или большой стабильный бесплатный лимит.
- Перед включением в Auto: сохранить ключ через существующий Keychain API; сделать fallback явным и ограниченным; показать выбранную модель, источник ответа и статус лимита/стоимости; проверить privacy/provider logging. Документация: [Quickstart](https://openrouter.ai/docs/quickstart), [Free Models Router](https://openrouter.ai/openrouter/free/apps), [FAQ: free tiers](https://openrouter.ai/docs/faq).

### Backend fallback implementation / Резервные маршруты backend — 2026-10-05

- Добавлен `openrouter` в whitelist секретов: macOS Keychain и `.env` fallback. UI позволяет сохранить его ключ и показывает настроенный маршрут из `/health`; по умолчанию `OPENROUTER_MODEL=openrouter/free`, а модель можно задать backend environment.
- Если пользователь явно разрешает платные маршруты, оркестратор параллельно собирает черновики Gemini Flash, настроенного предметного провайдера и Ollama; локальные модели проверяют черновики, а финальный этап по умолчанию использует Gemini 3.1 Pro Preview. По умолчанию действует отдельная free-only политика, описанная ниже.
- Ответы OpenRouter обрабатываются по тем же ограничениям request timeout/`max_tokens`, API key не уходит в UI, endpoint не настраивается пользователем. Настройки предупреждают, что доступность free-моделей и лимиты меняются, а платная model ID может взимать оплату.
- Актуальная таблица тарифов Gemini API помечает free tier для Gemini 3.1 Pro Preview как недоступный; в Auto интерфейс теперь предупреждает о возможной платной квоте. Это не live-оценка стоимости конкретного запроса, а предупреждение о тарифе модели. См. [официальную таблицу тарифов](https://ai.google.dev/gemini-api/docs/pricing) и [карточку модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-pro-preview).
- Настройки показывают настроенный router ID; после ответа SSE-подпись показывает model ID, который вернул OpenRouter. Если API его не вернул, подпись указывает настроенный маршрут и явно пишет, что разрешённое имя модели неизвестно. Это заявленное API-полем имя, не независимая проверка провайдера. В текущей рабочей копии добавлен ручной выбор провайдера/model ID specialist-слота по каждому предмету; настройка не редактирует остальные роли консилиума. Отображение фактических лимитов/стоимости и полноценная live-проверка ключа/модели ещё нужны. Free fallback не считается гарантированно бесплатным или постоянно доступным.

### Настраиваемый финальный синтез — 2026-10-06

- Control Center позволяет настроить provider/model ID именно финальной роли Auto: Automatic, Gemini, Kimi, OpenRouter или Ollama. Значение хранится локально отдельно от ключей. При разрешённых платных маршрутах Automatic использует Gemini Pro; free-only режим переопределяет Automatic на OpenRouter Free при заданном ключе или на локальный Ollama.
- Изменённый облачный маршрут при ошибке не переключается на другой облачный provider: финальный ответ использует локальный Ollama fallback, а выбранный и фактически использованный provider/model ID попадают в подпись ответа. Выбор Ollama ограничивается loopback endpoint.
- Эта настройка не меняет предметный specialist-слот черновика и не управляет критиком/verifier. Защита расходов Auto по умолчанию блокирует прямые Gemini/Kimi и платные model ID; выбор `openrouter/free` разрешён. Режим «Только локально» по-прежнему нужен, если вопрос не должен покидать Mac.
- Backend API и оркестратор покрыты тестами; GitHub Actions run [37381727625](https://github.com/invinby/coli-dev/actions/runs/37381727625) подтвердил Xcode build, backend packaging и smoke-test для Apple Silicon и Intel. Реальный запуск UI на Mac и доступность внешней модели/Ollama зависят от пользовательского Mac, API ключа, model ID и установленного сервиса.

### Free-only политика расходов Auto — 2026-10-06

- В новой установке разрешённые платные маршруты выключены. Cloud draft и финальный ответ используют только `openrouter/free`, если есть ключ OpenRouter; остальные draft/critic/verifier/финальный fallback используют Ollama на loopback. Gemini, Kimi и произвольные платные model ID не вызываются из обычного Auto до явного включения платных маршрутов в локальном Control Center.
- Это опирается на текущие официальные страницы поставщика: OpenRouter сообщает нулевую цену prompt/completion tokens у Free Models Router и текущий лимит бесплатного плана 50 запросов/день ([router](https://openrouter.ai/openrouter/free/apps), [тарифы и лимит](https://openrouter.ai/pricing/)). Набор выбранных моделей и лимиты меняются. Free-only не обещает качество конкретной модели или доступность сервиса; при отказе ответ завершает только локальная Ollama.
- Google Search grounding — отдельное действие, но оно подчиняется той же глобальной политике потенциально платных облачных вызовов, что и Auto. При выключенной политике backend блокирует поиск до сетевого обращения; UI не даёт включить переключатель. При разрешении пользователь принимает риск использования квоты/оплаты, о котором сообщает интерфейс.
- Политика хранится в локальном JSON без ключей; настройки loopback-only. Полный `.venv\Scripts\python.exe -m pytest 01_Projects -q` прошёл: 348 passed; Ruff, `compileall`, localization scan и `git diff --check` также прошли. GitHub Actions run [37384220248](https://github.com/invinby/coli-dev/actions/runs/37384220248) подтвердил backend, Xcode build arm64/Intel, packaging и smoke-test; реальная проверка UI на Mac всё ещё нужна.

### Главный синтезатор Auto — 2026-10-05

- Подтверждён порядок Auto-пайплайна: Gemini Flash, Kimi/OpenRouter и Ollama готовят независимые черновики параллельно; локальные critic/verifier проверяют подборку; Gemini 3.1 Pro Preview сравнивает варианты и формирует финальный ответ.
- Для одного запроса используется один финальный синтез вместо отдельного Pro-судьи плюс Flash-финализатора. В SSE-метаданных показываются фактический провайдер/model ID финального этапа и, если он известен, model ID ответа Kimi/OpenRouter.
- Если черновиков нет или финальная модель не отвечает, Auto переходит к локальному Ollama fallback. Недоступная локальная критика явно обозначается для финальной модели и не передаётся как будто это вывод агента.
- RU/EN настройки и экран тьютора объясняют отправку вопроса, найденных материалов и черновиков в облако и предупреждают, что Gemini API не предлагает free tier для Gemini 3.1 Pro Preview. «Только локально» остаётся отдельным маршрутом.
- Проверка этой правки на Windows: 193 теста прошли; одно существующее предупреждение Starlette/httpx о deprecated TestClient dependency. Mac GUI и live-провайдеры не запускались здесь; их сборка ожидает CI.

### Предметно-нейтральные рубрики Auto-консилиума — 2026-10-05

- Judge, критик и локальный verifier больше не считают, что каждый запрос про архитектуру ПО и Python. Они проверяют точность по предмету, логические шаги, соответствие контексту урока и уровню ученика, ясность, примеры, ограничения и неопределённость.
- Рубрики и финальный синтез формулируются на языке интерфейса RU/EN. Проверки синтаксиса, безопасности и производительности кода применяются только когда в задаче действительно есть код; `[K#]` citations сохраняются и не должны выдумываться.
- Автосохранение краткой заметки больше не создаёт пустую фоновую задачу, если локальный Obsidian bridge не настроен.
- Предметная настройка модели специалиста подключена к локальной панели: для шести направлений можно задать Gemini, Kimi, OpenRouter или Ollama либо вернуть общий автоматический выбор. Она управляет слотом специалиста в Auto-черновиках; финальный синтез и проверка остаются в общей цепочке.
- Секреты в маршруте не хранятся. Backend показывает наличие ключа/локального endpoint, но валидность model ID проверяется первым запросом. При отказе настроенного провайдера он исключается из fallback-попытки, а фактически использованные модели добавляются в подпись ответа и учёт usage.
- Полный каталог моделей, автоматическая проверка лимитов/цен, управление бюджетом и редактор всей многоагентной схемы остаются отдельными задачами. Нельзя объявлять модель бесплатной или «лучшей» без проверки условий и актуальности.

### Выбор провайдера и модели для ролей Auto — 2026-10-07

- В Control Center настраиваются отдельные провайдер и точный model ID для основного черновика, дополнительного черновика, критика и независимого проверяющего. Финальный синтезатор и предметные специалисты имеют отдельные маршруты в своих существующих разделах.
- Безопасные значения по умолчанию: основной черновик, критик и проверяющий работают через Ollama; дополнительный черновик использует Auto (OpenRouter Free при настроенном ключе, иначе Ollama). Gemini/Kimi/свой удалённый API не вызываются, пока пользователь явно не разрешит потенциально платные маршруты.
- В настройках каждой роли — включая существующие предметные маршруты и финальный синтез — показывается предупреждение: доступный cloud-вызов отправляет выбранному провайдеру вопрос, контекст курса и найденные материалы. Предупреждение отображается и когда Auto фактически разрешает OpenRouter Free.
- Маршрут исполняется по сохранённым provider/model ID, недоступный облачный free-маршрут может перейти на Ollama; запрещённый платный маршрут остаётся локальным. Пароли/API-ключи не добавляются в файл маршрутов.
- Backend-тесты покрывают сохранение и миграцию настроек, free-only gate, OpenRouter Free и выбор маршрута критика. Сборка SwiftUI, поведение приложения на macOS и live-провайдеры проверяются отдельно; успешные mock-тесты не подтверждают их.
## Реализация клиента — 2026-10-04

- Добавлены RU/EN и auto/local поля в POST /chat/stream; старые клиенты без них сохраняют русский язык и автоматический маршрут по умолчанию.
- SwiftUI-тьютор использует GET /health и SSE POST /chat/stream существующего локального оркестратора, отправляет контекст текущего урока и недавнюю историю диалога, показывает SSE-ответ по частям и позволяет прервать приём. Backend отправляет начальные SSE-байты до вызова провайдеров, а отключение клиента отменяет in-flight async генерацию. Local-only маршрут передаёт нативные NDJSON-чанки Ollama сразу через SSE; после завершения `done.answer` содержит ответ с проверенными RAG-цитатами, и SwiftUI заменяет им временный текст потока. Auto сначала собирает черновики и локальную критику, затем нативно стримит только финальный текст Gemini Pro через `streamGenerateContent?alt=sse`; промежуточные агентские черновики и части с `thought: true` ученику не показываются. Direct Google Search тоже стримит текст провайдера нативно, собирает incremental grounding metadata и проверяет наличие источников/Search Suggestions перед финальным событием. Для всех маршрутов `done.answer` остаётся проверенной финальной версией; при полном отказе Gemini Auto включает локальный фолбек, а не завершённый ответ не выдаётся как полный. Состояние авто-маршрута учитывает доступность облачного соединения, лимит сессий и наличие готовой Ollama-модели; сеть Ollama отдельно от облачного соединения.
- Добавлен начальный retrieval из живого Obsidian vault: приложение отправляет отдельный поисковый запрос вместе с предметом/уроком; backend передаёт найденные контекстные фрагменты в модель, просит использовать маркеры `[K#]` и возвращает пути/выдержки в SSE `done`. Каждый запрос ограничен четырьмя заметками и примерно 1.4 KB текста на заметку. В авто-режиме найденные выдержки могут уйти облачным моделям; локальный режим использует выбранный endpoint Ollama.
- Настройки предлагают автоматический и local-only маршруты. Чат блокирует local-only отправку, пока health API не подтвердит готовность Ollama-модели и loopback-адрес. Удалённые Ollama endpoints не получают запрос; Ollama-клиент не использует системные HTTP proxy. Obsidian REST разрешён только на loopback и не получает удалённые поисковые запросы. Автоматические запросы могут уйти настроенным облачным провайдерам. Gemini, Kimi и Obsidian keys можно сохранить через окно настроек в macOS Keychain; backend возвращает только configured/source, значение ключа не отдаётся. `.env` остаётся dev-fallback.
- Текущий retrieval объединяет живой Obsidian vault, автономный SQLite-индекс курсов и ограниченные лицензированные web-снимки. Курсный индекс обновляет изменившиеся файлы, разбивает Markdown на фрагменты с заголовками и номерами строк, а поиск работает офлайн лексически; при явной настройке loopback Ollama доступны кэшируемые семантические векторы и гибридное ранжирование. Python Tutorial и точная Python Language Reference страница про `assert`, две MedlinePlus Genetics basics-страницы и точная NIST SI Appendix B.9 страница попадают в отдельный web-RAG при успешной проверке; другие внешние страницы пока дают только метаданные. Найденные фрагменты сериализуются как JSON в пользовательское сообщение отдельно от system prompt; система просит считать их справочными данными, а не командами. Это снижает риск prompt injection, но не исключает его и не доказывает точность утверждений. Google Search grounding остаётся отдельным прямым opt-in маршрутом. Полноценный RAG для всех дисциплин, проверка соответствия утверждениям источников и безопасное автоматическое редактирование уроков не реализованы. Backend прошёл локальную проверку; macOS CI и ручное поведение на Mac требуют свежей сборки после публикации.
