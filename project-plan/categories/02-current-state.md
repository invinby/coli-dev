# 02. Текущее состояние ColiDev

## Подтверждено чтением текущего репозитория

- Python-проект с FastAPI и оркестратором ИИ-запросов.
- В README описаны отдельные режимы с облачными моделями, консилиумом и локальным режимом.
- Есть веб-интерфейс/API чата, потоковая выдача, проверка здоровья и статуса.
- Есть маршруты и worker для работы с Obsidian.
- Есть учебные заметки по Python/backend и соседним темам.
- Корень проекта уже привязан к приватному GitHub-репозиторию `invinby/coli-dev`; ветка `main` отслеживает `origin/main`.

## Начатый SwiftUI-клиент

`macOS/ColiDev/` содержит ранний Xcode-проект: локальный RU/EN-каталог шести предметов, учебные экраны, стартовые практики и девять отдельно написанных RU/EN-модулей: по одному для каждого направления и по одному дополнительному модулю для математики, физики и биологии. Новые модули доступны офлайн из Markdown внутри app bundle; каждый включает цель, теорию, практику, варианты ответа, правильный ответ с разбором, границы вывода и ссылки на источники. Перед завершением требуется правильный ответ и подтверждение ученика.

Это не законченный продукт: подключён RU/EN-чат с существующим FastAPI-оркестратором на localhost; реальное переключение локального/облачного маршрута на пользовательском Mac ещё не проверено запуском. Есть retrieval из подключённого Obsidian vault и постоянный SQLite-индекс Markdown-курсов. Индекс обновляет изменённые файлы, ищет без сети и возвращает цитаты, путь, строки, время получения и файловую дату изменения. Эта дата не подтверждает свежесть или точность фактов; у Obsidian дата изменения пока неизвестна. По умолчанию индекс использует лексический BM25-подобный поиск; необязательные локальные Ollama embeddings включаются через `OLLAMA_EMBEDDING_MODEL`, дополняют лексическое ранжирование и откатываются к нему при сбое. Код семантического пути прошёл mock-тесты, но работа с настоящей установленной моделью ещё не проверена; commit `b8f5cb4` прошёл 100 локальных backend-тестов и GitHub Actions. Commit `ddd87c5` прошёл сборку и bundle-check шести curriculum-файлов (run 37242014526); commit `ca41210` прошёл повторные backend checks, macOS build и bundle-check (run 37242458691). Commit `112ec62` с вращаемой SceneKit-визуализацией силы/массы прошёл backend checks и macOS build (run 37243523767). Полный набор 3D-симуляций не готов. UI проверен CI-сборкой, а не запуском на Mac. В Auto есть отдельный добровольный Google Search grounding: по умолчанию он отправляет только вопрос и контекст урока, без локального RAG; второй выключенный по умолчанию opt-in может добавить до четырёх фрагментов курса/Obsidian в тот же Gemini-запрос. Оба маршрута минуют агентный спор и не сохраняют ответ в Obsidian. Для отправки требуется подтверждение 18+, однако это не проверка возраста и не готовое ограничение аудитории для релиза. Это ещё не полный web-RAG с политикой надёжных источников и управляемым обновлением. Расширенные курсы и авторское наполнение, проверка авторитетности источников, полноценные 3D-симуляции, видеокаталог, синхронизация и полные интеграции ещё впереди.

Ключи Gemini, Kimi и Obsidian теперь можно ввести в SwiftUI-настройках: backend сохраняет их через `keyring.backends.macOS.Keyring`, а UI получает только источник и признак наличия. API отклоняет запросы не с loopback и чужой браузерный Origin; `.env` остаётся fallback. `Local-only` принимает Ollama только на localhost/loopback через отдельный HTTP-клиент без системных proxy; удалённый адрес блокируется до HTTP-вызова. Obsidian тоже ограничен loopback, удалённый REST endpoint не получает ключ или поисковый запрос. `/health` сообщает статус, а UI предупреждает и выключает неподтверждённый Local-only маршрут. CI run 37238373761 подтвердил базовый commit `18c98a5`; после добавления шести дорожных карт локально прошло 95 тестов, затем CI run 37239594309 успешно выполнил backend-проверки и сборку на GitHub-hosted macOS 15 / Xcode 16.4 для commit `325e74b`. Реальное чтение/запись пользовательского Keychain, живой Gemini grounding, Ollama на Mac и запуск приложения пока не проверены.

## Текущий инкремент — связанные уроки и повторение (2026-10-05)

- Каждая из шести приоритетных дорожных карт ссылается минимум на один доступный двуязычный модуль; математика включает функции и область определения/значений, физика — равнодействующую силу и кинетическую энергию, биология — осмос и наследование одного гена. SwiftUI открывает их по slug из bundle; проверка slug не позволяет строить произвольный путь.
- Контент одновременно остаётся в разрешённом локальном индексе RAG; backend-тесты подтверждают, что тематический RU/EN-запрос первым находит нужный урок.
- Уроки содержат предметные тренажёры, MC-проверку с двуязычными вариантами и разбором после правильного ответа. Событие завершения/review использует lesson ID, выбранная оценка вспоминания передаётся локальному SQLite-планировщику.
- Chat API принимает фиксированный предметный код и добавляет подходящую RU/EN проверочную рубрику для математики, английского, физики, биологии, зоологии или программирования. Рубрика доходит до всех ролей Auto, локального тьютора и отдельного Google-grounded пути; клиенты без предметного поля остаются совместимы. Отдельные модели по предметам пока не назначены.
- Backend записывает в отдельную SQLite базу только имена провайдера/модели, время ответа, факт наличия счётчиков и токены, которые вернули Gemini, Kimi, OpenRouter или Ollama. `/api/usage` ограничен loopback-проверкой, показывает 1–90 дней, хранит не больше 90 дней; тексты чатов и ключи не сохраняются. SwiftUI Settings показывает 30-дневную сводку. Это не расчёт стоимости и не жёсткий лимит расходов/токенов.
- Commit `e5ec472` запушен в `main`. GitHub Actions run [37249729913](https://github.com/invinby/coli-dev/actions/runs/37249729913) успешно выполнил backend suite и macOS 15/Xcode build, затем проверил curriculum и все шесть новых lesson-файлов в bundle. Локально `pytest 01_Projects -q` — 117 passed, одно предупреждение Starlette/httpx; `compileall`, проверка 80 строковых ключей и `git diff --check` прошли. Ручного запуска приложения на Mac по-прежнему не было.
- Это по одному содержательному примеру на предмет, а не полная программа. Живые провайдеры, ручной запуск на Mac, экспертная редактура всех курсов и остальные продуктовые интеграции остаются непроверенными/незавершёнными.
- Индекс и источник теперь различают файловый `modified_at` и авторский `source_checked_at` из Markdown frontmatter; заголовок убирается из RAG-выдержек, а исходные номера строк сохраняются. В prompt/UI есть оговорка: проверка списка ссылок не доказывает актуальность фактов. Commit `304717a`; run [37250882001](https://github.com/invinby/coli-dev/actions/runs/37250882001) зелёный по backend suite, macOS build и bundle-check. Локально прошло 121 тест; фактическая свежесть внешних источников не автоматизирована.

## Backend API guard — 2026-10-05

Loopback и Origin проверки распространены на health/status, сессии, tutor chat и все Obsidian-маршруты; настройки провайдеров и учебный прогресс уже используют ту же проверку. Тесты проверяют блокировку чужого Origin и удалённого клиента до обращения к локальным данным или провайдерам. Полный security-аудит остаётся открытым; сам сервер по-прежнему не имеет пользовательской аутентификации.

## OS-aware storage paths — 2026-10-05

Backend использует per-user пути ОС для индекса, состояния сессий, прогресса и логов; `COLIDEV_DATA_DIR` и `COLIDEV_LOG_DIR` позволяют задать отдельные директории. Существующие SQLite прогресса и JSON-сессий в прежних путях остаются доступны, пока новая база/файл не появятся. Windows больше не пишет логи и сессии в macOS-папку `~/Library`.

## Obsidian bridge hardening — 2026-10-05

Obsidian worker сам отвергает удалённые target URL до отправки Bearer token; перед построением endpoint проверяются и URL-кодируются vault-relative пути. Абсолютные пути, traversal, закодированные `..`, контрольные символы и чрезмерно длинные пути блокируются; API возвращает 422 на неверный путь. Commit `e1ee8db`; GitHub Actions run [37252817814](https://github.com/invinby/coli-dev/actions/runs/37252817814) прошёл backend checks и macOS build/bundle-check. Локальный backend suite: 160 тестов.

## Session state resilience — 2026-10-05

Файл квоты/режима сессий теперь загружается с проверкой схемы и размера; повреждённые записи сбрасываются безопасно. Запись идёт во временный файл с `fsync` и атомарным `replace`, чтобы прерванная операция не затёрла прежнее состояние. Unit-тесты передают временный путь вместо пользовательского app-data файла.

Полный локальный backend suite: 165 passed; `compileall` и `git diff --check` прошли. Commit `b5fc09c`; GitHub Actions run [37253372336](https://github.com/invinby/coli-dev/actions/runs/37253372336) успешно прошёл backend checks и macOS build/bundle-check.

## Request body limits — 2026-10-05

ASGI middleware ограничивает запросы размером 1 MiB до разбора JSON, включая chunked body, и проверяет согласованность `Content-Length`. Для tutor prompt/context и Obsidian write/search установлены отдельные максимумы; чрезмерный HTTP body возвращает 413, некорректный `Content-Length` — 400.

Локальный полный backend suite: 175 passed; `compileall` и `git diff --check` прошли. GitHub Actions run [37253856279](https://github.com/invinby/coli-dev/actions/runs/37253856279) успешно выполнил backend checks, macOS build и bundle-check.

## Напоминания о перепроверке источников RAG по графику автора — 2026-10-05

Индекс мигрирует nullable-колонку в существующей SQLite базе и возвращает дату/статус авторского напоминания. RU/EN-карточка источника и prompt называют это напоминанием, а не автоматической проверкой актуальности фактов. Сам график не загружает и не проверяет внешние материалы; отдельный ручной монитор ссылок описан ниже.

## Backend внутри `.app` и ручное обновление локального индекса — 2026-10-05

CI собирает отдельный PyInstaller runtime под arm64 и Intel, помещает его внутрь `ColiDev.app`, запускает API smoke-check и проверяет страницы курса в bundle. `LocalBackendSupervisor` запускает дочерний сервис при открытии клиента и останавливает его при завершении приложения. Новый раздел настроек запускает `POST /knowledge/refresh`: backend безопасно обновляет индекс встроенных учебных Markdown-файлов без вызова embeddings/провайдера, возвращает число документов и дату сканирования. Endpoint доступен только loopback-запросу с разрешённым Origin. Этот контроль не загружает интернет-материалы и не оценивает их фактическую свежесть.

## Ручная проверка ссылок на источники — 2026-10-05

Кнопка в Settings запускает loopback-only `POST /knowledge/sources/check`; монитор читает только встроенные `02_Areas/**/lessons/*.md` и принимает лишь точные HTTPS-ссылки на страницы четырёх фиксированных доменов: OpenStax, Python docs, British Council LearnEnglish и Animal Diversity Web. Произвольный URL пользователь передать не может; клиент не использует системный proxy, ограничивает параллелизм, таймаут и пакет из 20 ссылок, а редиректы не следует. Неподдерживаемые и пропущенные по лимиту ссылки показываются отдельно. Для доступных страниц SQLite хранит ETag/Last-Modified и дату проверки; повторный запрос использует условный GET. Тело страницы не читается, не кэшируется и не попадает в локальный RAG. Статус сообщает о доступности/изменении HTTP-валидатора, но не о качестве источника или свежести конкретного утверждения.

Полная редакторская проверка страниц, безопасная загрузка/разбор доверенного материала и включение содержимого в RAG остаются отдельной незавершённой работой.

В рабочей копии добавлена опциональная цепочка Kimi → OpenRouter: OpenRouter используется, когда ключ Kimi отсутствует или запрос Kimi завершается ошибкой; по умолчанию настроен маршрут `openrouter/free`. API key сохраняется через существующий Keychain endpoint, а Settings показывает настроенный маршрут и предупреждает про меняющиеся лимиты/возможную оплату. Запрос идёт только на фиксированный официальный OpenRouter endpoint. Ошибки провайдера не копируют тело HTTP-ответа в лог, а некорректный Kimi-ответ переводит цепочку на fallback. После backend-правки `ba1c8f0` Gemini 3.1 Pro Preview теперь формирует финальный ответ после локальной критики; OpenRouter сам по себе не делает приложение полностью работоспособным без Gemini.

## Состояние интеграции AI

Нативный клиент вызывает GET /health и POST /chat/stream на localhost. Язык ответа передаётся явно (ru/en), а старые API-клиенты сохраняют русский язык по умолчанию. Обычный Auto-запрос использует локальный индекс и Obsidian; найденные выдержки передаются как JSON-данные в сообщении ученика, отдельно от system prompt. Gemini получает system instruction и user content раздельно; в system instruction сказано считать выдержки недоверенными данными и не выполнять инструкции внутри них. Это снижает риск prompt injection, но не гарантирует безошибочное поведение модели. При разрешённой отправке фрагменты могут уйти настроенным облачным моделям. Отдельный opt-in Google Search отвечает на текущий вопрос с контекстом урока, ссылками на источники и Search Suggestions; по умолчанию не вызывает local retrieval, другие агенты и Obsidian save. Второй отдельный opt-in добавляет в этот запрос до четырёх совпавших выдержек курса/Obsidian; интерфейс предупреждает об отправке этих локальных данных в Google. Каждый доступный нативный урок можно сохранить как локальный Markdown-файл для ручного импорта в NotebookLM; автоимпорта и синхронизации нет. Экспорт собран и проверен в CI run [37262635710](https://github.com/invinby/coli-dev/actions/runs/37262635710) для Apple Silicon и Intel; реальный импорт в аккаунт NotebookLM не проверен. SSE начинает HTTP-ответ до локального retrieval/генерации, а отключение клиента отменяет in-flight async работу; текст модели пока буферизуется до выдачи чанками. Этот lifecycle прошёл 194 локальных теста и CI run [37263464753](https://github.com/invinby/coli-dev/actions/runs/37263464753) на backend и двух macOS-сборках. Тесты используют моки; live Gemini, Keychain пользователя, Ollama/Obsidian, NotebookLM и запуск `.app` не проверены. Полный web-RAG, видео, синхронизация и настоящий 3D не подключены. Удалён wildcard CORS, но полный аудит безопасности API остаётся отдельной задачей.
