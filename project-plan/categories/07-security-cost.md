# 07. Безопасность, приватность и стоимость

## Требования и цели

- Онлайн- и офлайн-режимы должны быть ясно различимы.
- Личные заметки и учебный прогресс должны оставаться локальными, если пользователь не включил облачную передачу.
- Пользователь должен понимать, какой контекст отправляется внешнему провайдеру.
- Пожелание о мощных моделях с бесплатными щедрыми лимитами требует проверки; приложение должно работать и при смене/исчерпании бесплатной квоты.

## Уже проверено

Локальный `.env` игнорируется Git и не найден в проверенной истории. Поиск распространённых шаблонов секретов в локальных файлах и доступных коммитах совпадений не дал, но это не полный аудит секретов. Репозиторий GitHub `invinby/coli-dev` публичный с 2026-10-05, поэтому его код и история доступны всем; любые секреты, которые могли туда попасть, следует считать раскрытыми и отозвать.

В текущем авто-маршруте найденные выдержки Obsidian вместе с вопросом передаются настроенному облачному провайдеру; SwiftUI-экран теперь сообщает об этом. Local-only принимает Ollama только по localhost/loopback; удалённый адрес блокируется backend до запроса. Obsidian Local REST API тоже ограничен loopback, его ключ не отправляется удалённому хосту, а удалённые vault-search вызовы пропускаются. Health сообщает статус, а UI предупреждает о неподтверждённых адресах.

Настройки Gemini, Kimi и Obsidian сохраняют ключи через `keyring.backends.macOS.Keyring`; backend отдаёт приложению только configured/source. Настройки, health/status, сессии, tutor chat, прогресс и все Obsidian-маршруты проверяют loopback-клиента и отклоняют посторонний Origin, если браузер его прислал. Входящие HTTP-тела ограничены 1 MiB до JSON-парсинга; ключевые chat/Obsidian-поля имеют отдельные пределы. Для записи ключей также заданы более строгий размер и формат тела, ошибки не содержат переданный секрет. Сам Obsidian worker принимает только loopback target URL и валидирует/кодирует vault-relative пути до HTTP-запроса. `.env` остаётся dev-fallback. Это частичная защита: localhost API не имеет user-account authentication, поэтому сервис нельзя открывать на внешнем интерфейсе; полный security-аудит и проверка живого desktop-потока ещё впереди.

Ошибки Kimi, Gemini и Ollama теперь логируют только HTTP-код или тип исключения; сырые тела ответов и текст исключения не попадают в журнал и в пользовательский fallback. Добавлены проверки, что отражённый текст ученика и API secret не появляются ни в логах, ни в ответах.

Проверка доступности Gemini отправляет ключ через HTTP-заголовок x-goog-api-key, а не в query string URL. Это соответствует официальному способу аутентификации Gemini API ([Google AI for Developers](https://ai.google.dev/api)); регрессионный тест проверяет точные аргументы запроса и отсутствие ключа в URL.

## Задачи

- Проверить реальный диалог доступа к Keychain и сохранение/чтение ключа на Mac при первом запуске; в CI проверяется импорт macOS backend, а не доступ к пользовательскому Keychain.
- Разделить секреты, личные данные, кэш курсов и публичные источники.
- Не логировать ключи, содержимое приватного vault и полный личный запрос без необходимости.
- Завершить полный аудит API-доступа, CORS, записи/удаления Obsidian и сетевых маршрутов; базовые loopback/Origin guards теперь покрывают локальные data/provider endpoints, но это не замена полному аудиту.
- Ограничивать вызовы моделей и показывать фактический расход/доступную квоту, если провайдер предоставляет эти данные.
- Не выдавать локальные сохранённые данные за свежие онлайн-факты; показывать дату синхронизации.
- Проверить лицензии библиотек, курсов, видео, 3D-моделей и способов интеграции.
