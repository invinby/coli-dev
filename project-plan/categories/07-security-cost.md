# 07. Безопасность, приватность и стоимость

## Требования и цели

- Онлайн- и офлайн-режимы должны быть ясно различимы.
- Личные заметки и учебный прогресс должны оставаться локальными, если пользователь не включил облачную передачу.
- Пользователь должен понимать, какой контекст отправляется внешнему провайдеру.
- Пожелание о мощных моделях с бесплатными щедрыми лимитами требует проверки; приложение должно работать и при смене/исчерпании бесплатной квоты.

## Уже проверено

Локальный `.env` игнорируется Git и не найден в истории. Проверка текущих файлов и достижимых коммитов по распространённым шаблонам секретов совпадений не дала. GitHub-репозиторий приватный.

В текущем авто-маршруте найденные выдержки Obsidian вместе с вопросом передаются настроенному облачному провайдеру; SwiftUI-экран теперь сообщает об этом. Local-only отправляет их на endpoint Ollama из серверной конфигурации, который может быть переопределён и потому должен проверяться перед обещанием on-device приватности.

Настройки Gemini, Kimi и Obsidian сохраняют ключи через `keyring.backends.macOS.Keyring`; backend отдаёт приложению только configured/source. Для этих маршрутов есть ограничение loopback, проверка Origin и ограничение размера/формата ввода с нейтральными ошибками, не содержащими переданное значение. `.env` остаётся dev-fallback. Это частичная защита: сам localhost API не имеет user-account authentication, поэтому сервис нельзя открывать на внешнем интерфейсе; полноценную авторизацию и аудит остальных маршрутов ещё нужно спроектировать.

## Задачи

- Проверить реальный диалог доступа к Keychain и сохранение/чтение ключа на Mac при первом запуске; в CI проверяется импорт macOS backend, а не доступ к пользовательскому Keychain.
- Разделить секреты, личные данные, кэш курсов и публичные источники.
- Не логировать ключи, содержимое приватного vault и полный личный запрос без необходимости.
- Провести полный аудит API-доступа, CORS, записи/удаления Obsidian и защиты сетевых маршрутов; текущие loopback/Origin проверки покрывают только маршруты ключей.
- Ограничивать вызовы моделей и показывать фактический расход/доступную квоту, если провайдер предоставляет эти данные.
- Не выдавать локальные сохранённые данные за свежие онлайн-факты; показывать дату синхронизации.
- Проверить лицензии библиотек, курсов, видео, 3D-моделей и способов интеграции.

## Замечание про логи

В прежней Git-истории есть небольшой `server.log` с демонстрационными HTTP-запросами. Перед приглашением других участников решить, нужно ли исключить логи из рабочей версии и/или очистить из истории.
