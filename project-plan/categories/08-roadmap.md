# 08. Этапы реализации

План предварительный; сроки определить после аудита. Все приоритетные направления и RU/EN предусмотрены с первого запуска. Полная траектория в каждом направлении должна вести от основ к углублённым темам; каталог можно расширять постепенно, показывая покрытие и пробелы, а не выдавая короткое введение за полный курс.

## Этап 3 — гибридный ИИ и актуальность

- Добавить абстракции локальных и облачных провайдеров.
- Построить RAG для курсов и разрешённых источников, с датами и цитатами.
- Локальный backend автоматически проверяет разрешённые официальные ссылки раз в 24 часа, когда приложение запущено, а временные ошибки повторяет через шесть часов; ручная проверка остаётся в Control Center. Монитор ограничен фиксированными HTTPS host/path правилами и не публикует изменения в уроки. В Control Center есть запрос короткого plain-text preview для точной ссылки из урока: максимум 512 KiB HTML/XML обрабатывается в памяти, редиректы и proxy запрещены, в UI передаётся максимум 4 000 символов, содержимое preview не сохраняется. Из preview можно подтвердить соответствие связанного урока показанной редакции источника: endpoint повторно загружает страницу, сравнивает digest, сохраняет дату/отпечаток в локальной SQLite-истории с лимитом 10 000 последних событий и не принимает старую версию после изменения. Реестр показывает историю сверок постранично с limit/cursor. Разрешённый web-RAG хранит ограниченные свежие снимки страниц Python Tutorial под PSF License Version 2, двух MedlinePlus Genetics summaries, точной NIST SI Appendix B.9 страницы и одного eLife CC BY 4.0 XML-файла; обязательны атрибуция и ссылка на условия, данные доступны только 48 часов после успешной проверки, до двух выдержек по 1 400 символов, если страница связана с уроком. В Control Center добавлен локальный RAG-инспектор: он показывает те же четыре фрагмента курсов/лицензированного web-RAG, что и обычный tutor retrieval, с citation IDs, датами и атрибуцией; если локальные embeddings настроены, индексирование может вызывать только loopback Ollama. Поиск в Obsidian выполняется только после отдельного явного переключателя. Инспектор не генерирует ответ и не вызывает Google Search или обновление внешних страниц. Нужны новые проверенные лицензии/источники, более полный редактор курса и безопасное расширение индекса без автопубликации.
- В консилиум добавлен optional OpenRouter specialist fallback для недоступного Kimi; ответный model ID провайдера теперь попадает в подпись ответа, если API его вернул. Control Center позволяет задать provider/model ID specialist-слота Auto для каждого предмета, отдельный маршрут финального синтеза и явный opt-in к платным Auto API. Free-only защита прошла 348 backend-тестов и GitHub Actions [37384220248](https://github.com/invinby/coli-dev/actions/runs/37384220248) на Apple Silicon/Intel. Полное управление всеми ролями Auto, динамическое измерение тарифа и проверка фактической доступности выбранного model ID остаются впереди.
- Auto-консилиум дополняет общие RU/EN рубрики предметной проверкой для шести валидируемых направлений; те же рубрики передаются локальному и Google-grounded tutor. Предметная маршрутизация и фоновый source-monitor уже собраны на Apple Silicon и Intel в GitHub Actions runs [37361969712](https://github.com/invinby/coli-dev/actions/runs/37361969712) и [37362813362](https://github.com/invinby/coli-dev/actions/runs/37362813362); SwiftUI-предпросмотр страницы успешно собран на Apple Silicon и Intel в GitHub Actions run 37364066357; CI не запускает UI.

## Общие критерии готовности и контрольные ворота

- В плане и отчётах различать написанный код, успешную сборку, автоматическую проверку и ручной запуск на устройстве; завершённым считать только то, что подтверждено нужным видом проверки.
- Для macOS-прототипа: чистая сборка и установка, запуск главного окна, навигация по всем шести направлениям, RU/EN, один полный урок с практикой и сохранением прогресса, проверка состояния backend, корректные сообщения об отсутствующих Ollama/Obsidian/сетевых сервисах.
- Для учебного релиза: у каждого направления есть редакторски проверенная карта последовательности, отмечены пробелы, урок содержит проверяемые цели, практику, критерий усвоения, ссылки и дату проверки; непроверенный материал явно помечен.
- Для ИИ/RAG: тестами подтверждены маршруты провайдеров и резервирование, ответы показывают фактически использованный маршрут и источники, бюджетные ограничения реально применяются там, где интерфейс называет их лимитами, локальные данные не уходят в сеть без явного согласия.
- Для визуализаций и медиа: каждый модуль связан с целью урока, имеет альтернативу при несовместимом устройстве/отключённой сети, показывает источник и права использования; ученик выполняет прогноз или задачу после просмотра/симуляции.
- Для релиза macOS: выполнить ручную проверку на поддерживаемом Mac, проверить установку/обновление/удаление и восстановление локальных данных, проверить безопасность, доступность и RU/EN; зафиксировать версию, инструкции и известные ограничения.
- Для Windows и сайта: проверить матрицу функционального паритета на чистой Windows-системе; проверить установщики и обновление для обеих ОС, контроль целостности и системные требования; ссылки сайта ведут только на подтверждённые релизные сборки.
