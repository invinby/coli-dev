# 08. Этапы реализации

План предварительный; сроки определить после аудита. Все приоритетные направления и RU/EN предусмотрены с первого запуска. Полная траектория в каждом направлении должна вести от основ к углублённым темам; каталог можно расширять постепенно, показывая покрытие и пробелы, а не выдавая короткое введение за полный курс.

## Этап 0 — зафиксировать продукт

- Уточнить аудиторию и карту всех важных направлений.
- Составить редакторски проверяемую карту всех шести приоритетных направлений: от основ до углублённых тем; перечисленные в плане траектории считать черновыми примерами.
- Подтвердить macOS и решить вопрос SwiftUI.
- Зафиксировать, что интерфейс и обучение доступны на русском и английском.
- Согласовать онлайн/офлайн, свежесть RAG, приватность и критерии готовности MVP.

## Этап 1 — аудит ColiDev

- Составить карту UI, API, оркестратора, провайдеров, Obsidian, учебных заметок и хранения.
- Отметить реализованное, устаревшее, неработающее и задуманное.
- Проверить безопасность и возможность повторно использовать backend.
- Не затрагивать XGENT.

## Этап 2 — macOS-основа и широкое учебное ядро

- Прототипировать нативную навигацию по актуальным Apple HIG на RU/EN.
- Для математики, английского, физики, биологии, зоологии и программирования подготовить последовательные траектории от базового к углублённому уровню, RU/EN и межпредметные связи.
- Поддержать язык UI, язык курса и язык ответа ИИ.
- Реализовать гибкий цикл занятия: цель/диагностика → объяснение → исследование → самостоятельная практика → обратная связь → проверка понимания → рекомендация следующего шага. Сохранять прогресс и интервальное повторение локально.
- Сквозной срез локального повторения теперь работает для десяти связанных уроков: SQLite-бэкенд, идемпотентные события, локальная очередь SwiftUI и карточка наступивших повторов используют lesson ID, подтверждённый quiz-ответ, оценку вспоминания и повтор из Today. Это ещё не расписание для каждого модуля будущей полной программы.
- Для зоологии доступен один начальный модуль; для программирования — вводный модуль и отдельный foundations-урок по переменным и типам; для английского — вводный модуль и один intermediate-урок; для математики, физики и биологии добавлены связанные модули, в том числе третий foundations-урок биологии про ДНК, гены, варианты и фенотипы. Полная учебная последовательность и редакторская проверка ещё нужны.

## Этап 3 — гибридный ИИ и актуальность

- Добавить абстракции локальных и облачных провайдеров.
- Построить RAG для курсов и разрешённых источников, с датами и цитатами.
- Локальный backend автоматически проверяет разрешённые официальные ссылки раз в 24 часа, когда приложение запущено, а временные ошибки повторяет через шесть часов; ручная проверка остаётся в Control Center. Монитор ограничен четырьмя HTTPS-доменами и не публикует изменения в уроки. В Control Center есть запрос короткого plain-text preview для точной ссылки из урока: максимум 512 KiB HTML обрабатывается в памяти, редиректы и proxy запрещены, в UI передаётся максимум 4 000 символов, содержимое не сохраняется и не попадает в RAG. Из preview можно подтвердить соответствие связанного урока показанной редакции источника: endpoint повторно загружает страницу, сравнивает digest, сохраняет дату/отпечаток в локальной SQLite-истории с лимитом 10 000 последних событий и не принимает старую версию после изменения. Реестр показывает историю сверок постранично с limit/cursor; дальше нужны правила лицензии/атрибуции, более полный редактор курса и безопасная локальная индексация одобренных выдержек в offline-RAG.
- В консилиум добавлен optional OpenRouter specialist fallback для недоступного Kimi; ответный model ID провайдера теперь попадает в подпись ответа, если API его вернул. Control Center позволяет задать provider/model ID specialist-слота Auto для каждого предмета, отдельный маршрут финального синтеза и явный opt-in к платным Auto API. Free-only защита прошла 348 backend-тестов и GitHub Actions [37384220248](https://github.com/invinby/coli-dev/actions/runs/37384220248) на Apple Silicon/Intel. Полное управление всеми ролями Auto, динамическое измерение тарифа и проверка фактической доступности выбранного model ID остаются впереди.
- Auto-консилиум дополняет общие RU/EN рубрики предметной проверкой для шести валидируемых направлений; те же рубрики передаются локальному и Google-grounded tutor. Предметная маршрутизация и фоновый source-monitor уже собраны на Apple Silicon и Intel в GitHub Actions runs [37361969712](https://github.com/invinby/coli-dev/actions/runs/37361969712) и [37362813362](https://github.com/invinby/coli-dev/actions/runs/37362813362); SwiftUI-предпросмотр страницы успешно собран на Apple Silicon и Intel в GitHub Actions run 37364066357; CI не запускает UI.
- Центр управления показывает локальный ledger фактических счётчиков Gemini/Kimi/OpenRouter/Ollama только там, где провайдер сам их вернул, с разбивкой по моделям. Это не вычисление стоимости и не enforced token budget; бюджетные блокировки и учёт актуальных тарифов всё ещё нужны.
- Первый RU/EN срез macOS-панели управления добавлен: обзор backend/индекса/плановых перепроверок, реестр ссылок, сервисы, Keychain-статусы и usage. В 2026-10-06 добавлены экспорт и merge-восстановление versioned JSON-копии учебного прогресса; это не включает полные backup настроек и SQLite-журналов, экспорт диагностики или редактор курсов/версий/решений. Эти административные функции остаются следующими частями панели; требования и безопасные границы зафиксированы в категориях 03, 06 и 07.
- Для каждого урока опираться на самую свежую доступную подходящую официальную редакцию; хранить provenance, даты и ссылки. Автоматические сигналы об изменении направляют материал на редакторскую RU/EN-проверку; автоматическая проверка URL не подтверждает факты и не должна незаметно публиковать новое содержимое.
- Сделать синхронизацию и понятное поведение при отсутствии сети.
- Добавить ограниченную оркестрацию специалистов с бюджетами и запасным маршрутом.

## Этап 4 — знания и интерактивное обучение

- В код добавлен двухсекундный опыт F = ma: постоянная суммарная сила, старт из покоя, без трения; запуск/пауза/сброс и шаг 0,1 с, отрицательная/нулевая сила, скорость и перемещение со знаком, фиксированная шкала метров. При Reduce Motion доступен пошаговый режим; изменение параметров сбрасывает опыт. Это ограниченная модель, не движок столкновений. Нужны сборка нового кода и ручная проверка на Mac: обе стороны дорожки, нулевая сила, пауза, повторный запуск, сворачивание, RU/EN и доступность.

- Согласовать и встроить Obsidian-сценарии.
- В нативной SwiftUI-сборке каждый урок экспортируется в Markdown через системный Save dialog; отдельная кнопка открывает NotebookLM. По официальной справке Markdown принимается как источник, но импорт выполняет сам пользователь. Дальше проверить это на реальном Mac/аккаунте и уточнять возможность официальной автоматизации, не заявляя её как готовую.
- Сделать учебные видео-сценарии и прототипы предметных интерактивов; проверить 3D-модуль, где ученик меняет параметры/детали и наблюдает процесс, а затем отвечает на вопрос или выполняет практику.

## Этап 5 — качество и выпуск macOS

- Проверить сборку на целевых версиях macOS и реальном оборудовании.
- Проверить RU/EN интерфейс и учебный контент, офлайн-сценарии, доступность UI, безопасность, восстановление данных и лимиты.
- После получения пользовательской иконки включить её в проект: сохранить исходник, подготовить совместимый AppIcon-набор и проверить отображение в Finder и Dock.
- Только после проверки обозначать macOS-приложение готовым к использованию.

## Этап 6 — Windows-паритет и дистрибуция

Этот этап начинается после готового и проверенного macOS-релиза.

- Зафиксировать текущую матрицу функций macOS и критерии паритета для Windows.
- Проверить повторное использование backend, доменных моделей и учебного контента; выбрать Windows UI-стек отдельным техническим решением.
- Реализовать Windows-клиент и адаптировать системные функции: хранилище ключей, пользовательские пути, работу локального backend/Ollama, офлайн-данные и восстановление.
- Проверить сценарии на чистых поддерживаемых версиях Windows и устранить расхождения с Mac по основным функциям.
- Подготовить установщики и обновление для обеих платформ; выбрать форматы, цифровую подпись, проверку целостности и правила версионирования.
- Запустить сайт загрузки с отдельными страницами для macOS и Windows и понятными системными требованиями. Пользователь получает установщик с сайта, а не через Git-клонирование.
- Открыть публичную загрузку только после проверки установщика, обновления и восстановления на чистых системах.

## Общие критерии готовности и контрольные ворота

- В плане и отчётах различать написанный код, успешную сборку, автоматическую проверку и ручной запуск на устройстве; завершённым считать только то, что подтверждено нужным видом проверки.
- Для macOS-прототипа: чистая сборка и установка, запуск главного окна, навигация по всем шести направлениям, RU/EN, один полный урок с практикой и сохранением прогресса, проверка состояния backend, корректные сообщения об отсутствующих Ollama/Obsidian/сетевых сервисах.
- Для учебного релиза: у каждого направления есть редакторски проверенная карта последовательности, отмечены пробелы, урок содержит проверяемые цели, практику, критерий усвоения, ссылки и дату проверки; непроверенный материал явно помечен.
- Для ИИ/RAG: тестами подтверждены маршруты провайдеров и резервирование, ответы показывают фактически использованный маршрут и источники, бюджетные ограничения реально применяются там, где интерфейс называет их лимитами, локальные данные не уходят в сеть без явного согласия.
- Для визуализаций и медиа: каждый модуль связан с целью урока, имеет альтернативу при несовместимом устройстве/отключённой сети, показывает источник и права использования; ученик выполняет прогноз или задачу после просмотра/симуляции.
- Для релиза macOS: выполнить ручную проверку на поддерживаемом Mac, проверить установку/обновление/удаление и восстановление локальных данных, проверить безопасность, доступность и RU/EN; зафиксировать версию, инструкции и известные ограничения.
- Для Windows и сайта: проверить матрицу функционального паритета на чистой Windows-системе; проверить установщики и обновление для обеих ОС, контроль целостности и системные требования; ссылки сайта ведут только на подтверждённые релизные сборки.
