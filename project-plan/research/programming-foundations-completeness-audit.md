# Programming Foundations completeness audit / Аудит полноты Programming Foundations

**Audit date / Дата аудита:** 2026-10-12  
**Repository state / Состояние репозитория:** `codex/ai-role-routing` at `69c39fd`  
**Scope / Объём:** Read `02_Areas/Programming/curriculum.md` and all nine Markdown files in `02_Areas/Programming/lessons/`; compared the six linked Foundations outcomes and the two linked Intermediate outcomes with lesson text, RU/EN parity, examples, practice prompts, answer keys, and official Python/SQLite documentation. This is an editorial/source review only: no lesson, application, or roadmap files were changed, no code was executed, and no tests were run.  
Прочитаны `02_Areas/Programming/curriculum.md` и все девять Markdown-файлов в `02_Areas/Programming/lessons/`; шесть связанных результатов уровня Foundations и два связанных результата Intermediate сопоставлены с текстом уроков, паритетом RU/EN, примерами, заданиями, ключами ответов и официальной документацией Python/SQLite. ## Overall result / Общий результат

**EN:** All six Foundations rows in the roadmap point to lesson files, but link coverage is not the same as outcome coverage. The basic examples and answer keys reviewed are factually sound, and no RU/EN answer or meaning mismatch was found. The main remaining gaps are that the “input and output” outcome has no user-input practice, the “loops” outcome teaches only `for` (not `while`), and the Git outcome is named but not taught as an actionable workflow. The separately routed `intro.programming` lesson also repeats conditions, claims to refer to an example that is absent from the file, and gives an under-specified practice prompt. The two linked Intermediate lessons also cover only slices of their broader roadmap outcomes.

**RU:** Все шесть строк Foundations в дорожной карте связаны с файлами уроков, но наличие ссылки не означает, что результат обучения полностью покрыт. Проверенные базовые примеры и ключи ответов фактически корректны; смысловых расхождений RU/EN и ошибок в ответах не найдено. Основные пробелы: результат «ввод и вывод» не включает практику пользовательского ввода; в теме «циклы» разбирается только `for`, без `while`; Git упомянут, но практический рабочий процесс не объяснён. Отдельно маршрутизируемый урок `intro.programming` повторяет условия, ссылается на отсутствующий в файле пример и содержит недостаточно определённое задание. Два связанных Intermediate-урока также покрывают лишь часть широких результатов своей дорожной карты.

### Intermediate links do not yet satisfy their full outcomes / Уроки Intermediate пока не закрывают полные результаты

**EN:** This is outside the immediate Foundations gap list, but it affects whether the current programming sequence matches its roadmap. `search_and_complexity.md` compares linear and binary search and mentions `bisect` insertion cost; it does not teach selecting among data structures by required operations or analyze space trade-offs, both of which the roadmap outcome names. `sql_transactions.md` illustrates two `UPDATE`s with `BEGIN`/`COMMIT`/`ROLLBACK` and explains ACID, but it does not design a table/schema, develop a `SELECT` query, or use an index as promised by the SQL outcome. These are partial starter lessons, not full coverage of the linked topics.

**RU:** Это не основной пробел Foundations, но он важен для соответствия всей последовательности дорожной карте. `search_and_complexity.md` сравнивает линейный и бинарный поиск и упоминает стоимость вставки через `bisect`; он не учит выбирать структуру данных под операции и не разбирает компромисс по памяти, хотя это прямо указано в результате дорожной карты. `sql_transactions.md` показывает два `UPDATE` внутри `BEGIN`/`COMMIT`/`ROLLBACK` и объясняет ACID, но не проектирует таблицу/схему, не строит `SELECT` и не использует индекс, как обещано в результате по SQL. Сейчас это начальные фрагменты тем, а не их полное покрытие.

**EN:** The SQL example is internally consistent as a teaching model. The SQLite-specific claims about explicit transactions, nested `BEGIN` being invalid, `SAVEPOINT`, and the single concurrent writer are correctly bounded to SQLite, and the lesson explicitly warns that database behavior varies. Do not generalize that concurrency detail to every SQL database.

**RU:** Пример SQL внутренне согласован как учебная модель. Утверждения о ручных транзакциях, запрете вложенного `BEGIN`, `SAVEPOINT` и единственной одновременной пишущей транзакции верно ограничены SQLite; урок отдельно предупреждает о различиях между СУБД. Это правило о конкурентной записи нельзя переносить на все SQL-базы.

## Official source checks / Сверка с официальными источниками

**EN:** The lesson facts sampled for this audit are consistent with the current official references: Python `/` returns a float; assignment rebinds names to values; strings and lists support sequence behavior; `for` traverses sequence items in order; `enumerate()` is the intended index/value tool; `input()` returns text; `with` performs cleanup even when processing raises; and exception handlers select matching types. The list’s `append()` and `IndexError` behavior is correct. `bisect` finds a position in sorted data and `insort` remains `O(n)` due to list insertion. SQLite’s transaction caveats are also correctly scoped. No factual repair is required by this review; the findings above concern coverage, traceability, and assessment depth.

**RU:** Проверенные фактические утверждения согласуются с актуальными официальными источниками: `/` в Python возвращает `float`; присваивание связывает имя со значением; строки и списки поддерживают поведение последовательностей; `for` проходит элементы в заданном порядке; для пар индекса и значения предусмотрен `enumerate()`; `input()` возвращает текст; `with` выполняет очистку и при исключении; обработчик исключений выбирается по типу. Поведение `append()` и `IndexError` указано правильно. `bisect` ищет позицию в отсортированных данных, а `insort` остаётся `O(n)` из-за вставки в список. Оговорки SQLite также даны корректно. В этой проверке нет требования к фактическому исправлению; выводы выше относятся к покрытию, прослеживаемости и глубине проверки знаний.
