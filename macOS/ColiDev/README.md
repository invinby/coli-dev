# ColiDev for macOS

An early native SwiftUI client for the ColiDev learning platform. Open `ColiDev.xcodeproj` in Xcode on a Mac and run the `ColiDev` scheme.

## Included in this first slice

- Native macOS navigation for Today, Subjects, lesson sessions, the Control Center, and general Settings.
- Russian and English interface and lesson content, switchable in the toolbar and persisted locally.
- Six subject starters: mathematics, English, physics, biology, zoology, and programming.
- Each subject now has a bilingual local curriculum roadmap indexed for offline tutor retrieval, covering foundations, intermediate and advanced themes, and suggested practice. These files define coverage only; they are not yet full lessons or an academically reviewed syllabus.
- Each subject has an authored bilingual foundation lesson; Mathematics, English, Physics, and Biology also link follow-up lessons on domain and range, Present Perfect contrast, work and kinetic energy, constant acceleration, and Mendelian inheritance. The constant-acceleration lesson links to the force-motion lab for a prediction-and-observation exercise. The lesson screen reads bundled Markdown offline, separates objective, explanation, practice, self-check, limitations, and source links, and opens the tutor with that lesson's context. The backend's local RAG index retrieves the same files without a second copy.
- Each current starter lesson separates the theory, mechanism, example, and limitations in Russian and English; the tutor receives all four blocks as lesson context.
- Six foundation-practice modules, one per subject, cover function graphs, present-simple/continuous choices, force and mass, a simplified osmosis model, animal adaptation, and conditional branching. Follow-up practice adds a Mathematics graph lab, a Physics work/energy visualization, a Biology Punnett-square trainer, a 3D DNA helix, and a rotatable SceneKit model of an animal cell with selectable organelles and RU/EN explanations. Each linked lesson has a bilingual multiple-choice check with a worked explanation; completion requires a correct answer and learner confirmation. Recall ratings and due dates are recorded by lesson ID in the local spaced-repetition backend.
- Immediate answer feedback and local completion progress. Once a correct check and learner confirmation are present, review events are stored locally and synced to the backend's SQLite SM-2 scheduler; repeated reviews update the next due date. Unsent events remain in UserDefaults and use event IDs so retries do not create duplicate reviews.
- A lesson-aware RU/EN tutor connects to the local FastAPI orchestrator at 127.0.0.1:8000, displays SSE response chunks, and offers automatic or local-only routing. The client sends a validated subject code; the backend appends a domain-specific bilingual review rubric to Auto, local, and grounded requests. The Control Center can choose a specialist-draft provider/model ID per subject, configure the final synthesizer, and set separate loopback Ollama model IDs for the Auto local draft, critic, and verifier. It can also list installed models from the local Ollama endpoint for selection; this only reads model IDs and does not download models. Those three roles stay local; other Auto drafts and the final response can still use cloud providers under the global cost policy. Choose Local Only in Settings when the whole tutor request must stay on this Mac. The CI-packaged `.app` embeds the backend runtime, starts it on app launch, and stops its child process when the app exits; a plain Xcode build still needs a separately running backend unless the packaging script is run.
- The backend keeps an incremental SQLite keyword index of curated Markdown under `02_Areas/` and Markdown/text cheat sheets under `03_Resources/Cheatsheets/`. It refreshes changed files while handling tutor questions, searches locally without network access, and combines up to four course/Obsidian excerpts with `[K#]` citations.
- Before streaming a tutor answer, the backend checks that each `[K#]` marker matches a source ID returned for that answer. Unmatched markers are replaced and shown as a RU/EN warning; this does not prove that a matching source supports the nearby claim. Code spans and fenced code blocks are left intact.
- Retrieved course sources show their repository path, line span, filesystem modification time, retrieval time, and (when authored in Markdown frontmatter) source-reference check date separately. The UI labels the latter as note metadata, not proof that facts are current. YAML frontmatter is omitted from indexed excerpts while original line numbers are preserved. The current Obsidian search response does not supply a reliable edit time, so the app labels that date unavailable.
- Each curriculum lesson now shows its authored source-review date beside the cached monitor state for its official links, including the last HTTP/content check and per-lesson review schedule when available. Changed, unavailable, unchecked, or not-monitored states stay explicit; the screen says these signals do not verify lesson facts. The read-only status comes from the loopback backend's existing source inventory and does not trigger a new external fetch when opening a lesson.
- Course RAG citations also carry source titles and canonical HTTPS URLs from the six-domain allowlist. The tutor sends this provenance as untrusted JSON alongside each local `[K#]` excerpt, and SwiftUI links to the approved official pages in the citation card. This is a link to the curriculum's stated source, not proof that the linked page supports the nearby fact; only exact Python Tutorial, MedlinePlus Genetics basics, and NIST Guide to the SI Appendix B.9 pages enter web-content RAG under their documented reuse terms. Other pages, including OpenStax textbooks, remain metadata/preview-only unless their use rights are cleared for the product.
- The database is stored per user (`~/Library/Application Support/coli-dev/knowledge.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/knowledge.sqlite3` on Windows, or the XDG data directory on Linux). Backend `/health` reports the indexed-document count, last index check, and counts for author-scheduled reviews that are due or missing; the Control Center shows these counts and can manually refresh the local course index without contacting external services. While the local backend is running, an automatic source monitor checks lesson links about every 24 hours; temporary network failures retry after six hours. Manual checks remain available in the Control Center. The monitor only requests exact lesson links on six fixed domains (Animal Diversity Web, British Council LearnEnglish, MedlinePlus, NIST, OpenStax, and Python docs). It reads at most 512 KiB of an HTML response to extract a page title, short description, and normalized-text SHA-256 fingerprint in memory. Bounded normalized page text is persisted for RAG only for exact Python Tutorial, MedlinePlus Genetics DNA/gene basics, and NIST SI Appendix B.9 paths with documented reuse terms and required attribution; other monitored source bodies remain metadata-only. Fresh RAG snapshots expire after 48 hours without a successful check. Redirects are blocked, and shared URLs retain all linked lessons and their author-review dates, intervals, and due states. These signals identify changes for an editor; they do not verify lesson facts or automatically update lesson content.
- Spaced-repetition progress uses a separate per-user SQLite file (`~/Library/Application Support/ColiDev/learning-progress.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/learning-progress.sqlite3` on Windows, or the XDG data directory on Linux). `COLIDEV_DATA_DIR` overrides its parent folder. The backend exposes only loopback-guarded read/write routes; cross-device account sync is not implemented.
- The Control Center shows a 30-day provider-usage summary from local SQLite (`provider-usage.sqlite3` under ColiDev's per-user data directory), including a per-model breakdown. Gemini, Kimi, OpenRouter, and Ollama token counts are included only when their responses report them; missing counts are not estimated. Only provider/model names, timestamps, response counts, and usage counters are stored, with 90-day retention. No chat text or API keys are saved there. This view does not calculate provider charges or enforce a spending/token cap.
- Gemini, Kimi, OpenRouter, and Obsidian API keys can be entered in the Control Center's Services pane and are saved by the local backend to macOS Keychain. The backend reports only whether a key exists and where it came from; it never returns the value. Ordinary Auto blocks paid routes by default: it may send one draft and the final synthesis through the exact `openrouter/free` route when an OpenRouter key is configured, while other agent roles and cloud-failure fallbacks use loopback Ollama. Without the key, Auto remains local. An explicit, separately saved Control Center setting allows potentially paid Gemini, Kimi, or custom OpenRouter models. Free-model pools and provider limits can change, and the client cannot guarantee an account's quota. `.env` remains a development fallback. Auto may send the learner's question and retrieved excerpts to OpenRouter; local-only mode sends them only to an Ollama endpoint on a loopback address. The backend blocks remote Ollama and Obsidian URLs.
- A full lesson can be copied to the configured local Obsidian vault from the lesson page. Each save gets a unique dated Markdown path under `ColiDev/Lessons/<subject>/`, so repeated saves do not overwrite an earlier note. NotebookLM has no connected write API in this app; its supported path remains an explicit Markdown export followed by user-initiated import.
- The tutor has a separate, opt-in Google Search action in Auto mode. After an 18+ confirmation, it sends the current question and lesson context directly to Gemini, shows inline citations and Google's Search Suggestions, and bypasses the other agents. Local retrieval is off by default; a second, off-by-default checkbox can add up to four matching course/Obsidian excerpts for that request, with a warning that those local excerpts will be sent to Gemini/Google. This path does not save its answer to Obsidian. Google stores grounding prompts, context, and output for up to 30 days; unpaid quota may be used to improve Google's services and processed by human reviewers. Search may use quota or incur charges, so do not send sensitive information.

## Current boundary

The first Control Center slice adds Overview, Courses, Sources, and Services panes, per-subject specialist-model routing, and separate local Ollama models for Auto draft, critic, and verifier roles. Courses reports bundled lesson files, bilingual assessment structure, source-link presence, and how many roadmap topics link to usable full lessons. It now audits each bundled lesson for non-empty goal, theory, practice, self-check question/options/answer/explanation, and limitations in both Russian and English, plus a shared official-source section; missing fields are listed by lesson. These structural signals do not certify accuracy, editorial quality, or completeness. The installed-model menu reads from Ollama only when its URL is loopback; the backend returns validated model IDs only. It shows local backend/index status, scheduled review counts, per-model usage, provider and Obsidian readiness, safe secret status, and the bounded source inventory, including website title/description and the content-check date. The source registry can be searched by subject, reference, or lesson and filtered by review state. It separates author-entered `source_checked` from the last HTTP check and the server's `Last-Modified` header. The Overview pane can export a JSON diagnostic report containing app/system details, backend and source-monitor counters, structural curriculum coverage, and reported provider/model usage. It deliberately omits API-key values, chat messages, learner reflections, and source page text. A course editor/revision workflow, broader source-body ingestion into RAG, and cloud routing for critic/verifier remain future work.

The Sources pane also offers an on-demand preview of up to 4,000 characters from an exact approved lesson URL. The backend reads at most 512 KiB of HTML, blocks redirects and system proxies, and returns only page metadata and an in-memory excerpt. It does not save page text or add the excerpt to RAG; a changed source still needs a human editor to review it.

After comparing the excerpt with a lesson, an editor can explicitly confirm that the lesson still matches that source version. The backend fetches the page again and refuses the confirmation if its text fingerprint changed since the preview. Per-user SQLite retains the latest 10,000 review events as URL, lesson path, digest, and review date/time; it never stores the excerpt or rewrites Markdown. A paginated history viewer shows 50 records per request; full course revision remains future work.

This is the beginning of implementation, not the complete product. Local retrieval uses bounded lexical/BM25-style ranking; it is not semantic vector search by default and does not validate source authority. Retrieved excerpts are serialized as JSON in the learner message, separate from system instructions; this reduces prompt-injection risk but cannot guarantee model behavior. Six course roadmaps remain coverage outlines. The repository currently contains 25 bilingual lesson files; each priority direction has at least a foundation lesson, with additional lessons in Mathematics, English, Physics, Biology, Zoology, and Programming. This is not a complete or academically reviewed curriculum, and there is no curated cheatsheet collection yet. Google Search can include local course/Obsidian excerpts for one answer after a separate opt-in, but remains a single-request grounding path rather than indexed web-RAG and may use quota or incur charges regardless of the ordinary Auto free-only policy. Scheduled and manual source checks cover six fixed domains, with at most 50 approved pages per pass. Bounded web-RAG text is limited to exact Python Tutorial, public-domain MedlinePlus Genetics DNA/gene basics, and distributable NIST SI Appendix B.9 paths; other monitored source bodies remain metadata-only. OpenStax is explicitly shown as metadata-only with its general CC BY-NC-SA 4.0 reuse restriction; page-specific exceptions and release rights need review before source-text caching. The monitor does not fact-check local lessons or publish changed material automatically. Comprehensive source ingestion, license-reviewed expansion, factual review workflow, and review of web results remain unfinished. Each lesson can be exported as local Markdown and opened in NotebookLM for manual import; direct API integration and synchronization remain unimplemented. A broad verified course library, source-quality checks, direct vault browsing, real video sourcing, and additional subject-specific 3D simulations still need separate slices. The force/mass SceneKit lab models a bounded two-second experiment from rest under constant net force, with play/pause/reset, 0.1 s stepping, signed velocity and displacement, and a fixed spatial scale. It excludes friction and collisions; the work/energy scene remains illustrative, and the zoology visual modules are 2D previews, while the cell scene is a qualitative 3D model. The collision lab now compares ideal elastic and perfectly inelastic outcomes with conserved-quantity readouts; these new collision controls still need physical Mac acceptance. The intended audience, use case, and supported regions must be settled before distribution: current Gemini API terms restrict use to people aged 18+ and professional or business use, and the in-app confirmation is not age verification. The backend sends initial SSE bytes before retrieval/provider work and propagates client disconnect cancellation to in-flight async generation. It streams native provider chunks for local Ollama, Gemini final/grounded responses, and final synthesis through the configured OpenAI-compatible API or OpenRouter. Final Kimi paths still return buffered answers. Account/sync also remains future work.

The project targets macOS 13+. GitHub Actions builds the SwiftUI app, embeds the local backend runtime, and smoke-tests the packaged backend API and tutor page. CI does not launch the SwiftUI app itself. The app has not yet been launched and exercised on a user's Mac, and live provider/Obsidian/Ollama behavior remains unverified.
