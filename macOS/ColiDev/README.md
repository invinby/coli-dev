# ColiDev for macOS

An early native SwiftUI client for the ColiDev learning platform. Open `ColiDev.xcodeproj` in Xcode on a Mac and run the `ColiDev` scheme.

## Included in this first slice

- Native macOS navigation for Today, Subjects, lesson sessions, the Control Center, and general Settings.
- Russian and English interface and lesson content, switchable in the toolbar and persisted locally.
- Six subject starters: mathematics, English, physics, biology, zoology, and programming.
- Each subject now has a bilingual local curriculum roadmap indexed for offline tutor retrieval, covering foundations, intermediate and advanced themes, and suggested practice. These files define coverage only; they are not yet full lessons or an academically reviewed syllabus.
- Each subject has an authored bilingual foundation lesson; Mathematics, English, Physics, and Biology also link follow-up lessons on domain and range, Present Perfect contrast, work and kinetic energy, and Mendelian inheritance. The lesson screen reads bundled Markdown offline, separates objective, explanation, practice, self-check, limitations, and source links, and opens the tutor with that lesson's context. The backend's local RAG index retrieves the same files without a second copy.
- Each current starter lesson separates the theory, mechanism, example, and limitations in Russian and English; the tutor receives all four blocks as lesson context.
- Six foundation-practice modules, one per subject, cover function graphs, present-simple/continuous choices, force and mass, a simplified osmosis model, animal adaptation, and conditional branching. Follow-up practice adds a Mathematics graph lab, a Physics work/energy visualization, and a Biology Punnett-square trainer. Each linked lesson has a bilingual multiple-choice check with a worked explanation; completion requires a correct answer and learner confirmation. Recall ratings and due dates are recorded by lesson ID in the local spaced-repetition backend.
- Immediate answer feedback and local completion progress. Once a correct check and learner confirmation are present, review events are stored locally and synced to the backend's SQLite SM-2 scheduler; repeated reviews update the next due date. Unsent events remain in UserDefaults and use event IDs so retries do not create duplicate reviews.
- A lesson-aware RU/EN tutor connects to the local FastAPI orchestrator at 127.0.0.1:8000, displays SSE response chunks, and offers automatic or local-only routing. The client sends a validated subject code; the backend appends a domain-specific bilingual review rubric to Auto, local, and grounded requests. This guides quality checks but does not yet choose different models per subject. The CI-packaged `.app` embeds the backend runtime, starts it on app launch, and stops its child process when the app exits; a plain Xcode build still needs a separately running backend unless the packaging script is run.
- The backend keeps an incremental SQLite keyword index of curated Markdown under `02_Areas/` and Markdown/text cheat sheets under `03_Resources/Cheatsheets/`. It refreshes changed files while handling tutor questions, searches locally without network access, and combines up to four course/Obsidian excerpts with `[K#]` citations.
- Before streaming a tutor answer, the backend checks that each `[K#]` marker matches a source ID returned for that answer. Unmatched markers are replaced and shown as a RU/EN warning; this does not prove that a matching source supports the nearby claim. Code spans and fenced code blocks are left intact.
- Retrieved course sources show their repository path, line span, filesystem modification time, retrieval time, and (when authored in Markdown frontmatter) source-reference check date separately. The UI labels the latter as note metadata, not proof that facts are current. YAML frontmatter is omitted from indexed excerpts while original line numbers are preserved. The current Obsidian search response does not supply a reliable edit time, so the app labels that date unavailable.
- Course RAG citations also carry source titles and canonical HTTPS URLs from the four-domain allowlist. The tutor sends this provenance as untrusted JSON alongside each local `[K#]` excerpt, and SwiftUI links to the approved official pages in the citation card. This is a link to the curriculum's stated source, not proof that the linked page supports the nearby fact; the bounded source check reads page metadata/text transiently, but full source content is not ingested into RAG.
- The database is stored per user (`~/Library/Application Support/coli-dev/knowledge.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/knowledge.sqlite3` on Windows, or the XDG data directory on Linux). Backend `/health` reports the indexed-document count, last index check, and counts for author-scheduled reviews that are due or missing; the Control Center shows these counts and can manually refresh the local course index without contacting external services. Its source pane checks lesson links on four fixed domains (OpenStax, Python docs, British Council LearnEnglish, and Animal Diversity Web). It reads at most 512 KiB of an HTML response to extract a page title, short description, and normalized-text SHA-256 fingerprint in memory. Only that metadata/fingerprint and HTTP validators are stored; the full body is not persisted or added to RAG. Redirects are blocked, and shared URLs retain all linked lessons and their author-review dates, intervals, and due states. These signals identify changes for an editor; they do not verify lesson facts or guarantee freshness.
- Spaced-repetition progress uses a separate per-user SQLite file (`~/Library/Application Support/ColiDev/learning-progress.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/learning-progress.sqlite3` on Windows, or the XDG data directory on Linux). `COLIDEV_DATA_DIR` overrides its parent folder. The backend exposes only loopback-guarded read/write routes; cross-device account sync is not implemented.
- The Control Center shows a 30-day provider-usage summary from local SQLite (`provider-usage.sqlite3` under ColiDev's per-user data directory), including a per-model breakdown. Gemini, Kimi, OpenRouter, and Ollama token counts are included only when their responses report them; missing counts are not estimated. Only provider/model names, timestamps, response counts, and usage counters are stored, with 90-day retention. No chat text or API keys are saved there. This view does not calculate provider charges or enforce a spending/token cap.
- Gemini, Kimi, OpenRouter, and Obsidian API keys can be entered in the Control Center's Services pane and are saved by the local backend to macOS Keychain. The backend reports only whether a key exists and where it came from; it never returns the value. Auto collects Gemini Flash, Kimi/OpenRouter, and Ollama drafts, has Ollama review them, then uses Gemini 3.1 Pro Preview for the final answer. OpenRouter is an optional cloud-draft fallback when Kimi is missing or fails; its configured route defaults to `openrouter/free`, whose available models and limits can change. Gemini 3.1 Pro Preview has no free Gemini API tier, and paid model IDs may incur charges. `.env` remains a development fallback. In automatic mode, the question, retrieved excerpts, and candidate drafts may be sent to configured cloud providers. Local-only mode sends them only to an Ollama endpoint on a loopback address; the backend blocks remote Ollama and Obsidian URLs.
- The tutor has a separate, opt-in Google Search action in Auto mode. After an 18+ confirmation, it sends the current question and lesson context directly to Gemini, shows inline citations and Google's Search Suggestions, and bypasses the other agents. Local retrieval is off by default; a second, off-by-default checkbox can add up to four matching course/Obsidian excerpts for that request, with a warning that those local excerpts will be sent to Gemini/Google. This path does not save its answer to Obsidian. Google stores grounding prompts, context, and output for up to 30 days; unpaid quota may be used to improve Google's services and processed by human reviewers. Search may use quota or incur charges, so do not send sensitive information.

## Current boundary

The first Control Center slice adds Overview, Sources, and Services panes. It shows local backend/index status, scheduled review counts, per-model usage, provider and Obsidian readiness, safe secret status, and the bounded source inventory, including website title/description and the content-check date. The source registry can be searched by subject, reference, or lesson and filtered by review state. It separates author-entered `source_checked` from the last HTTP check and the server's `Last-Modified` header. It does not yet provide a course editor/revision workflow, source-body ingestion into RAG, per-subject model assignment, a diagnostic export, or backup/restore.

This is the beginning of implementation, not the complete product. Local retrieval uses bounded lexical/BM25-style ranking; it is not semantic vector search by default and does not validate source authority. Retrieved excerpts are serialized as JSON in the learner message, separate from system instructions; this reduces prompt-injection risk but cannot guarantee model behavior. Six course roadmaps remain coverage outlines. Each priority direction has a foundation lesson, with one follow-up each in Mathematics (domain and range), English (Present Perfect contrast), Physics (work and kinetic energy), and Biology (Mendelian inheritance); the set is not a complete or academically reviewed curriculum, and there is no curated cheatsheet collection yet. Google Search can include local course/Obsidian excerpts for one answer after a separate opt-in, but remains a single-request grounding path rather than indexed web-RAG. The manual source checker covers four fixed domains, reads a bounded HTML response in memory, and saves only page metadata, a normalized-text fingerprint, and HTTP validators; it does not ingest source bodies into RAG or fact-check local lessons. Comprehensive source ingestion/synchronization, factual review workflow, and review of web results remain unfinished. Each lesson can be exported as local Markdown and opened in NotebookLM for manual import; direct NotebookLM API integration and synchronization remain unimplemented. A broad verified course library, source-quality checks, direct vault browsing, real video sourcing, and additional subject-specific 3D simulations still need separate slices. The existing physics SceneKit view is a visualization, not a motion simulation; the biology and zoology visual modules are 2D previews. The intended audience, use case, and supported regions must be settled before distribution: current Gemini API terms restrict use to people aged 18+ and professional or business use, and the in-app confirmation is not age verification. The backend sends initial SSE bytes before retrieval/provider work and propagates client disconnect cancellation to in-flight async generation; it still buffers the provider's full answer before emitting word chunks, so true model-token streaming remains future work. Account/sync also remains future work.

The project targets macOS 13+. GitHub Actions builds the SwiftUI app, embeds the local backend runtime, and smoke-tests the packaged backend API and tutor page. CI does not launch the SwiftUI app itself. The app has not yet been launched and exercised on a user's Mac, and live provider/Obsidian/Ollama behavior remains unverified.
