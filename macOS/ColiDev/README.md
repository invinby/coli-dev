# ColiDev for macOS

An early native SwiftUI client for the ColiDev learning platform. Open `ColiDev.xcodeproj` in Xcode on a Mac and run the `ColiDev` scheme.

## Included in this first slice

- Native macOS navigation for Today, Subjects, lesson sessions, and Settings.
- Russian and English interface and lesson content, switchable in the toolbar and persisted locally.
- Six subject starters: mathematics, English, physics, biology, zoology, and programming.
- Each subject now has a bilingual local curriculum roadmap indexed for offline tutor retrieval, covering foundations, intermediate and advanced themes, and suggested practice. These files define coverage only; they are not yet full lessons or an academically reviewed syllabus.
- Each roadmap links one authored bilingual foundation lesson. The lesson screen reads the bundled Markdown offline, separates objective, explanation, practice, self-check, limitations, and source links, and opens the tutor with that lesson's context. The backend's local RAG index can retrieve these same files; it does not maintain a second copy.
- Each current starter lesson separates the theory, mechanism, example, and limitations in Russian and English; the tutor receives all four blocks as lesson context.
- One interactive practice module per subject: a live function graph, sentence builder, force/mass simulation, selectable cell diagram, animal adaptation explorer, and conditional-code runner.
- The six linked foundation lessons have topic-matched practice: function graph, present-simple/continuous choices, force and mass with the existing rotatable SceneKit view, a simplified osmosis model, animal adaptation exploration, and conditional branching. Each also has a bilingual multiple-choice check with a worked explanation; completion requires a correct answer and learner confirmation. Recall ratings and due dates are recorded by lesson ID in the local spaced-repetition backend.
- Immediate answer feedback and local completion progress. Once a correct check and learner confirmation are present, review events are stored locally and synced to the backend's SQLite SM-2 scheduler; repeated reviews update the next due date. Unsent events remain in UserDefaults and use event IDs so retries do not create duplicate reviews.
- A lesson-aware RU/EN tutor connects to the local FastAPI orchestrator at 127.0.0.1:8000, displays SSE response chunks, and offers automatic or local-only routing. The CI-packaged `.app` embeds the backend runtime, starts it on app launch, and stops its child process when the app exits; a plain Xcode build still needs a separately running backend unless the packaging script is run.
- The backend keeps an incremental SQLite keyword index of curated Markdown under `02_Areas/` and Markdown/text cheat sheets under `03_Resources/Cheatsheets/`. It refreshes changed files while handling tutor questions, searches locally without network access, and combines up to four course/Obsidian excerpts with `[K#]` citations.
- Before streaming a tutor answer, the backend checks that each `[K#]` marker matches a source ID returned for that answer. Unmatched markers are replaced and shown as a RU/EN warning; this does not prove that a matching source supports the nearby claim. Code spans and fenced code blocks are left intact.
- Retrieved course sources show their repository path, line span, filesystem modification time, retrieval time, and (when authored in Markdown frontmatter) source-reference check date separately. The UI labels the latter as note metadata, not proof that facts are current. YAML frontmatter is omitted from indexed excerpts while original line numbers are preserved. The current Obsidian search response does not supply a reliable edit time, so the app labels that date unavailable.
- The database is stored per user (`~/Library/Application Support/coli-dev/knowledge.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/knowledge.sqlite3` on Windows, or the XDG data directory on Linux). Backend `/health` reports the indexed-document count, last index check, and counts for author-scheduled reviews that are due or missing; Settings shows them and can manually refresh the local course index without contacting external services. These schedules are editorial reminders and do not automatically verify factual freshness.
- Spaced-repetition progress uses a separate per-user SQLite file (`~/Library/Application Support/ColiDev/learning-progress.sqlite3` on macOS, `%LOCALAPPDATA%/ColiDev/learning-progress.sqlite3` on Windows, or the XDG data directory on Linux). `COLIDEV_DATA_DIR` overrides its parent folder. The backend exposes only loopback-guarded read/write routes; cross-device account sync is not implemented.
- Gemini, Kimi, OpenRouter, and Obsidian API keys can be entered in Settings and are saved by the local backend to macOS Keychain. The backend reports only whether a key exists and where it came from; it never returns the value. Auto collects Gemini Flash, Kimi/OpenRouter, and Ollama drafts, has Ollama review them, then uses Gemini 3.1 Pro Preview for the final answer. OpenRouter is an optional cloud-draft fallback when Kimi is missing or fails; its configured route defaults to `openrouter/free`, whose available models and limits can change. Gemini 3.1 Pro Preview has no free Gemini API tier, and paid model IDs may incur charges. `.env` remains a development fallback. In automatic mode, the question, retrieved excerpts, and candidate drafts may be sent to configured cloud providers. Local-only mode sends them only to an Ollama endpoint on a loopback address; the backend blocks remote Ollama and Obsidian URLs.
- The tutor has a separate, opt-in Google Search action in Auto mode. After an 18+ confirmation, it sends the current question and lesson context directly to Gemini, shows inline citations and Google's Search Suggestions, and bypasses the other agents. Local retrieval is off by default; a second, off-by-default checkbox can add up to four matching course/Obsidian excerpts for that request, with a warning that those local excerpts will be sent to Gemini/Google. This path does not save its answer to Obsidian. Google stores grounding prompts, context, and output for up to 30 days; unpaid quota may be used to improve Google's services and processed by human reviewers. Search may use quota or incur charges, so do not send sensitive information.

## Current boundary

This is the beginning of implementation, not the complete product. Local retrieval uses bounded lexical/BM25-style ranking; it is not semantic vector search by default and does not validate source authority. Retrieved excerpts are serialized as JSON in the learner message, separate from system instructions; this reduces prompt-injection risk but cannot guarantee model behavior. Six course roadmaps remain coverage outlines, with one authored sample foundation lesson linked from each; they are not complete or academically reviewed curricula, and there is no curated cheatsheet collection yet. Google Search can now include local course/Obsidian excerpts for one answer after a separate opt-in, but remains a single-request grounding path rather than indexed web-RAG; trusted-source rules, web freshness controls, and review of web results are still missing. Each lesson can now be exported as a local Markdown source and opened in NotebookLM for manual import; direct NotebookLM API integration and synchronization remain unimplemented. A broad verified course library, trusted-source and freshness controls, source-quality checks, direct vault browsing, real video sourcing, and additional subject-specific 3D simulations still need separate slices. The existing physics SceneKit view is a visualization, not a motion simulation; the biology and zoology visual modules are 2D previews. The intended audience, use case, and supported regions must be settled before distribution: current Gemini API terms restrict use to people aged 18+ and professional or business use, and the in-app confirmation is not age verification. The backend sends initial SSE bytes before retrieval/provider work and propagates client disconnect cancellation to in-flight async generation; it still buffers the provider's full answer before emitting word chunks, so true model-token streaming remains future work. Account/sync also remains future work.

The project targets macOS 13+. GitHub Actions builds the SwiftUI app, embeds the local backend runtime, and smoke-tests the packaged backend API and tutor page. CI does not launch the SwiftUI app itself. The app has not yet been launched and exercised on a user's Mac, and live provider/Obsidian/Ollama behavior remains unverified.
